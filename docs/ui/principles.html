UI の基本方針

Yat Tat Ta の画面を作るときの決まり事です。新しい部品を足すときに、既存の画面と並べて違和感が出ないようにするためのもの。このドキュメントのサイトではなく、アプリの画面についての方針です。

画面の主役は、完了連打のボタンです。叩くたびにスクワットがドパに変わる、その1打を気持ちよくすることに、ほかのすべてを従わせます。

01 / color

色

色は意味ごとに1つです。ドパは dopa、押せるものは gold、休み券は signal。DT の棒も、DPW の数字も、ドパに関わるものはすべて dopa で描きます。金色のボタンが2つ並んだら、どちらかは押せるものではありません。

暗い配色は iPhone の表示設定に従います。夜食のあとに開く人が多いので、暗い配色を後回しにはしません。入れ替えるのは地と文字と枠だけで、dopa、gold、signal はどちらでも同じ色です。金色のボタンの文字は、暗い配色でも ink のままにします。

02 / shape

形と影

枠は ink の太い線（2〜4pt）、影はぼかさずに右下か真下へずらします。押すと沈むおもちゃの見た目です。押せるものほど影を厚くします。カードは右下に 4pt。完了連打では、押し込む代わりにスクワット隊がしゃがみます。叩いたことを、音と振動より先に目で返すためです。

角は丸くします。カードは 16pt 前後、ボタンは真円か両端の丸い形。直角は使いません。

03 / type

文字

数字は SF Pro Rounded の Heavy で描きます。日数も、ドパも、目標回数も、画面で大きく出るのは数字だからです。桁が増えても幅が揺れないよう、等幅の数字を使います。このドキュメントの見本では、近い形の M PLUS Rounded 1c で代えています。

日本語はシステムフォント（ヒラギノ）の Bold か Black。地の文の細い字は使いません。片手で叩きながら目の端で読む画面なので、読ませる文は1行で終わる長さにします。

04 / layout

置き方

縦画面だけです。連打の途中で横に倒れると、叩く場所が動いて指が外れます。

ホームは上から、連続記録の帯、叩く場所、DPW と DT のカードの順。叩く場所は帯とカードのあいだの全部で、画面の幅いっぱいに取ります。そこにスクワット隊が立ち、隊の上に残りの数を大きく出します。2026-10-06 までは、ここに金色の丸いボタンを置いていました。的が大きいほど、連打で指が外れにくい。重ねる部品（フィナーレ、途切れたときのカード、休み券の帯、通知の問いかけ）は、ホームの上に出して用が済めば消します。画面を増やして遷移させることはしません。

05 / touch

叩いたときの返し方

タップは、指が触れた瞬間に受けます（UIKit の touchesBegan）。SwiftUI のボタンは指を離したときに反応するので、連打の速さに追いつきません。複数の指で叩けば、1本ずつ数えます。手触りの試作で決めたことの引き継ぎです。

光は指の位置から広がる輪で出し、画面全体の明滅は弱くします。連打で画面全体が強く明滅すると、光に敏感な人の負担になるからです。画面の四辺の光は連打の速さで強まり、止まると落ちます。

06 / motion

動きを減らす設定

iPhone の「視差効果を減らす」が入っているときは、粒と画面の揺れを止めます。残すのは、数字の変化、指の位置の輪、文字と札。ひかえめモードの考え方です。音と振動は変えません。

連打の途中は、ドパドパの段階（NORMAL、CHANCE、激熱、PUSH）で隊の色、背景の放射線、揺れが変わります。どれだけ盛っても、画面全体の明滅は1秒に3回までです。

激熱からは、画面全体が舞台になります。地が暗転し、虹の放射線が画面の端まで回る。ドパ突破、フィーバータイム、筋肉確定、ねぎらいは、画面全体に重ねて出します。ただし、上の連続記録の帯と下のカードは、自分の地を持ったまま残します。暗転した地の上でも、日数とドパが読めるようにするためです。重ね物は指を通し、連打を止めません。

白く光らせる明滅は、どの演出を足しても合わせて1秒に3回までです。使うのは、段階に入った1打、ドパ突破、確定の閃光だけ。速い連打の1打ごとに光らせると、1秒に8回を超えるからです。PUSH の膨らみや炎のちらつきのように、明るさを大きく変えない動きは数えません。

フィーバーの地のように色を流す演出は、1秒に1周より速くしません。色相がそれより速く入れ替わると、白く光らせなくても明滅に近い負担になるからです。「スクワット 残り」の数のパーティーパロット風の色の巡りも、この速さに合わせている。

07 / words

文言

責めない文を書きます。「昨日は休みましたね」「連続記録が途切れそうです！」のような、失うことを先に見せる文は使いません。途切れたときも「0日」とは出さず、「今日の1回で1日目」と、次の1回で起きることを書きます。

健康効果は画面に書きません。「血糖値」「糖質の吸収」といった言葉は出さず、筋肉確定のような冗談も、体の中で起きることには触れません。画面で体について書くのは、設定シートの一番下の注意書きだけです。決まり事は 健康効果の書き方。

文言は String Catalog に集めます。開発言語は日本語です（課題 localization）。
