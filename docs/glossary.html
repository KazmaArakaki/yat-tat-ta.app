#kakutei-enshutsu

確定演出／煽り演出

パチンコの文法を借りた演出。煽り演出は結果を見せる前に段階を踏んで期待を高めるもので、ドパ電卓は NORMAL、CHANCE、激熱、PUSH、シャッター、暗転、復活、PREMIUM と進む。確定演出は到達が決まったことを告げるもので、ドパ九九の「虹ドパ」が当たる。語彙として先バレ、激熱、PUSH、虹がよく使われる。

#fixed-vs-variable-reward

確定報酬と可変報酬

確定報酬は、行動すれば必ず決まった報酬が入る仕組み。可変報酬は、報酬が出るかどうかや量が毎回ぶれる仕組みで、スロット型と呼ばれる。分析者はドパドリルを「確定報酬のセッション内増幅」とし、可変報酬とは違うと評している。ドパドリル系は課金、ランキング、可変報酬を持たない。
Yat Tat Ta は、スクワット1回で1ドパの確定報酬で作ってきた。例外はフィーバータイムで、始まるかどうかを1打ごとに 0.51% のくじで決める可変報酬になる（2026-10-06 開発者が決定）。

#tezawari

手触り

指が画面に触れてから、音、振動、光が返ってくるまでの体感。本プロジェクトの差別化の本体。調査の段階では、タップ、音、振動、光の4つがずれなくそろうことを売りにするつもりで Swift を選んだ。2026-10-06 の試作で、音を 150ms 遅らせても開発者の指は気づかなかったため、軸を「演出を盛っても止まらないこと」へ置き直した。Web で作られたドパ〇〇の失敗例（ドパ九九）も、ms 単位のずれではなく処理落ちだった。題材を毎食後スクワットに決めてからは、手触りが問われるのは、スクワットの回数だけ叩く完了連打になった。Claude は振動も音の遅れも感じ取れないため、良し悪しは開発者が実機で判断する。

用例

開発者手触りって、演出が派手かどうかとは違うんですか。

ドメインエキスパート違います。派手さは後から盛れます。手触りは、叩いたら必ず返ってくるかどうかです。盛ったせいで返事が途切れたら、手触りは壊れます。

開発者題材を決める前に試作するのはなぜですか。

ドメインエキスパートドリルでも電卓でも、土台は同じ「叩いたら返ってくる」だからです。ここが気持ちよくなければ、題材を何にしても差別化になりません。

#sync-drift

同期ずれ

1回のタップに対する音、振動、光が、別々の時刻に届くこと。原因は経路ごとの遅れの違いで、音は出力バッファ、振動はアクチュエーター、光は画面の書き換え（60Hz なら最大約17ms、120Hz なら約8ms）を待つ。手触りの試作では、音を AVAudioEngine、振動を Core Haptics で別々に鳴らす「A 別々」と、Core Haptics の1つのパターンで両方を鳴らす「B 一体」を比べる。音だけをわざと 0〜150ms 遅らせて、何 ms から気づくかも確かめた。結果は、A と B の違いが分からず、150ms でも気づかなかった（開発者1人、iPhone 15 Pro）。

用例

開発者画面の「タッチ→発火」が 20ms 前後で出ていれば、同期ずれはないと言えますか。

ドメインエキスパート言えません。あれは iOS がタッチを届けてから、命令を出し終えるまでの時間です。音がスピーカーから出るまで、振動が手に届くまでは、アプリの中からは測れません。

開発者じゃあ何で判断するんですか。

ドメインエキスパート指です。わざと音を遅らせて、気づき始める ms を探しました。150ms でも気づかなかったので、ずれの小ささは売りになりません。気にするべきは処理落ちのほうです。

X のアカウント @yattattadotcom の投稿と返事の下書きを書く AI。アカウントの名前の「広報兼サポート担当」にあたる。下書きは Claude Code の会話に出し、開発者が直して X のアプリから手で出す。AI が自分で投稿することはしない。自己紹介の「作った本人（とAI）」の AI はこれ。

用例

開発者広報担当AI に任せたら、毎日勝手に投稿してくれるんですか。

ドメインエキスパート書くところまでは任せられます。出すのは開発者で、X のアプリから手で出します。

開発者質問が来たら、自動で答えてくれますか。

ドメインエキスパート返事の下書きは書きます。出すのは投稿と同じく開発者です。AI が書いた返信を自動で出すには、X の事前の承認が要ります。

#ai-label

AI ラベル

広報担当AI が書いた X の投稿の頭に置く「🤖」。出すのは開発者の手でも、文を AI が書いたことを読む人に見せるための印。開発者が自分で書いた投稿には付けない。開発者が半分以上を書き直したら外す。自己紹介で 🤖 の意味を説明する（2026-10-08、開発者の注文）。

用例

開発者ぼくが少し直してから出すなら、AI が書いたとは言えないんじゃないですか。

ドメインエキスパート言い回しを直したくらいなら、🤖 は残します。半分以上を書き直したら、あなたの投稿として外してください。

開発者文の最後じゃなくて、頭に置くのはなぜですか。

ドメインエキスパート長い投稿は途中で折りたたまれます。頭の1文字なら、必ず見えます。

#promo-post

宣伝投稿

広報担当AI の投稿のうち、アプリを勧めるもの。App Store のリンク、動画、機能のどれかを見せる。リンクがなくても、勧めていれば宣伝に数える。残りは雑談投稿で、何も売らない。割合は雑談8割、宣伝2割。宣伝投稿には、下書きの段階で出してから24時間の目標（表示、いいね、リポスト）を置き、24時間後に達成か未達かを記録する（2026-10-08、開発者の注文）。

用例

開発者スクワットマンが「今日は60回しゃがんだ」とだけ言う投稿は、宣伝ですか。

ドメインエキスパート雑談です。アプリを勧めていないので。ここに「食後のスクワットを記録するアプリ」と足したら宣伝です。

開発者目標の数は、どうやって決めるんですか。

ドメインエキスパート最初の3本は仮の数です。そのあとは、これまでの宣伝の中央値の1.2倍にします。

#source-stock

紹介のストック

広報担当AI が紹介に使う論文と X のポストをためておく場所（marketing/x/sources.json）。読んで確かめた中身（対象、比べたこと、要旨の結果）と、題名や誌名に病名が入るかどうかを残す。紹介に使ったら、投稿の URL を書き足す。同じ論文は、型や切り口を変えれば何度紹介してもよい（2026-10-08、開発者の注文）。

用例

開発者面白そうなポストを見つけたら、どうすればいいですか。

ドメインエキスパートURL を会話に貼ってください。紹介のストックに足しておき、紹介の番が来たら使います。

開発者同じ論文を何回も紹介してもいいんですか。

ドメインエキスパートいいです。ただ、前と同じ文にはしません。使ったものには投稿の URL が付くので、前の型を見て、別の型や数字で書きます。

#weekly-review

週の振り返り

広報担当AI の研究の紹介と小ネタを、1週間まとめて目標と比べること。研究の紹介はブックマークと引用の中央値、小ネタは返信の中央値と、アカウントのフォロワーの週の増えを見る。数は X の API で読む（2026-10-09 に、取れる数に替えた）。次の週に増やす型と減らす型を決め、次の週の目標（前の週の中央値の1.2倍）を置く。宣伝は1本ごとに見るので含めない。週は日曜〜土曜で、日曜に前の週の表示のまとめと一緒に振り返る（2026-10-10、開発者の注文）。最初の週（2026-10-08〜10-10）は、根拠のない仮の目標で始めた。

用例

開発者小ネタは1本ごとに当たり外れを決めないんですか。

ドメインエキスパートフォロワーが少ないうちは、1本ごとの差はたまたまで決まりがちです。週の振り返りで、まとめて中央値を見ます。

開発者根拠のない目標でも、置く意味はありますか。

ドメインエキスパート外れた幅が、次の週の目標の手がかりになります。

#pinned-post

固定ポスト

X のプロフィールの一番上に固定しておく投稿。@yattattadotcom では、自己紹介と型D（保存版）の研究カードを1本にまとめて置く。返信やハッシュタグで見つけてプロフィールに来た人が、何のアカウントかを1本で分かり、フォローするか決められるようにするため（2026-10-11、開発者が採用）。

用例

開発者返信を見てプロフィールに来た人は、何を見るんですか。

ドメインエキスパート自己紹介の文と、一番上の固定ポストです。そこで「また見たい」と思えなければ、フォローせずに帰ります。
