features/記録する

完了連打

スクワットを終えたら、その回数だけボタンを叩く。1打ごとにスクワット1回が1ドパに変わる。記録を作るのは、アプリの中でこの機能だけです。

01 / overview

何を叩いているのか

毎食後スクワットでは、アプリはスクワットを数えません。数えるのは本人で、アプリが受け取るのは「終わった」という合図だけです。その合図を1回の押下ではなく、目標回数と同じ数の連打にしたのが完了連打です。20回しゃがんだら20打。

ボタンに出ている数は、まだドパに変えていないスクワットの数です。1打で1減り、その1がドパの粒になって飛んでいく。済ませたスクワットを、自分の指でドパに替える作業になります。アプリはスクワットをしたかを確かめません。他人と比べる場所がないので、ごまかして困るのは本人だけです。

表1　決まりごと

項目値理由
1打の重さスクワット1回 = 1ドパドパに使い道はない。回数と同じものを、ためていく数として見せる。
目標回数既定 20。設定で 5〜100、5刻み食後20回ほど、という開発者の動機から。叩き始めた時点の値をその記録の最後まで使う。
いつ叩けるかいつでも、何度でも間食や夜食のあとも記録したい。1日の上限は置かない。
複数の指1本ずつ1打に数える手触りの試作と同じ。指が触れた瞬間に受ける（離したときではない）。

02 / closing

記録が1件になるまで

最初の1打で、記録が1件開きます。叩くたびに画面の中のドパ、DPW、DT が1ずつ増え、開いた記録は次の3つのどれかで閉じます。閉じるまで記録は画面の中にだけあり、閉じた瞬間に1回だけ端末へ保存します。1打ごとに書き込むと、タップの瞬間の仕事が増えるからです。

閉じる 1

残りが0になった

最後の1打。フィナーレを出す。そのあと1.2秒は叩いても数えない。勢い余った指で次の記録が始まらないように。

閉じる 2

60秒叩かなかった

叩いたところまでで1件。フィナーレは出さず、ボタンは目標回数に戻る。スクワットを終えてから叩くので、途中で1分空くのはやめたときだけ。

閉じる 3

アプリを離れた

ホームに戻った、電話が来た。2 と同じ閉じ方。離れたまま終了されても、叩いた分は消えない。

7打で止めた記録も、7ドパの1件として残り、その日の連続記録もつながります。継続の条件は「その日に完了連打を1回」で、目標回数に届いたかは問いません。閉じないまま待ち続けると、昼に7打で止めた人が夜に開いたとき、ボタンに「13」が残ってしまいます。

間違えて叩いた記録を消す仕組みはない（開発者が決定）。課題 undo-record。アプリが異常終了したときは、開いていた1件が消える。

03 / effects

1打ごとの演出と、最後の1打

演出は、ドパドリルの演出インフレと同じく、最後に向けて強くなります。強さの決め方は、出すものごとに分けています。音程を叩く速さで決めると、ゆっくり叩く人は最後まで低い音のままになる。かといって速さを捨てると、手触りの試作で「気持ちいい」と言われた連打の勢いが消えます。

表2　何で強さを決めるか

出すもの強さを決めるもの
音の高さ、振動の強さ進み具合。目標回数を8つに割り、何打目かで8段階のどれかを鳴らす。最後の1打がいちばん高く強い
ボタンの光、指の位置の輪連打の速さ。0.45秒以内に次を叩くと明るくなり、止まると落ちる
ドパの粒いつも同じ。1打で1粒、ボタンから「+N ドパ」へ飛ぶ

残りが0になる1打では、フィナーレが重なります。粒が弾け、「やったった！」の文字、和音、長めの振動。その日最初の記録なら連続記録の日数がめくれ、節目に届いていれば札が1枚ずつ下に積まれます。節目の中身はドパの合計と連続記録と休み券に書いています。

  • 音：外部の音素材を持たず、起動時に8段階ぶん合成しておく。マナーモードでは鳴らさない（.ambient）。ほかのアプリの音楽は止めない。
  • 粒：CAEmitterLayer で出す。粒の動きを GPU 側で計算し、1打ごとのメインスレッドの仕事を増やさない。足りるかは課題 heavy-effects-performance で実機確認。
  • 視差効果を減らす：iPhone のこの設定が入っていれば、粒と画面の揺れを止め、数字の変化と輪だけにする（ひかえめモードの考え方）。
