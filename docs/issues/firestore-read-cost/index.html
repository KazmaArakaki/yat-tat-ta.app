起動のたびに全部の記録を読む費用

優先度：低 状態：未着手

概要

いまの設計では、アプリは自分の記録をすべて Firestore から読み、DT や連続記録を計算する。
記録が増えるほど、起動のたびの読み取り回数が増えていく。

どれくらい増えるか

1日に3回叩く人なら、1年で約1,100件になる。Firestore は読んだ文書の数で数えるので、全部を読み直すと1回で約1,100回の読み取りになる。Firestore の説明によると、つなぎっぱなしの読み込みでも、30分以上切れてからつなぎ直すと全部を読み直した扱いになる。食事のたびに開くアプリなので、開くたびにほぼ全部を読むと見ておく。

無料で使える読み取りは1日5万回（執筆時点の公開値）。1年使った人の起動が、全員合わせて1日に45回を超えると、無料の枠を出る計算になる。超えた分の単価は地域で違うので、Firebase の料金表で確かめる。

直し方の候補

  1. 増えた分だけ読む：端末のキャッシュにある記録はキャッシュから読み、サーバーには「前回より後に届いた記録」（createdAt で絞る）だけを聞く。消した記録は伝わらないので、消す代わりに「消した」印を立てる形に変える必要がある。createdAt は今回の設計で先に足してある。
  2. 日ごとの合計を置く：記録とは別に、日ごとの合計を持つ。読む数は日数まで減るが、計算した数を保存しないというデータベースの方針に反する。選ぶなら方針から見直す。
優先度が低の理由
1人あたりの記録が千件を超えるのは、使い始めて1年ほどたってから。利用者が少ないうちは無料の枠に収まる。
先送りにした理由
リリース前で、利用者も記録もまだない。全部を読むほうが作りが単純で、記録と画面の数が食い違わない。Firebase の使用量の画面で、読み取りが1日3万回を超えたら取りかかる。

見つけたセッション：記録を Firestore に移す
