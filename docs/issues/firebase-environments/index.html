開発用と本番用の Firebase を分け、App Check を入れる

優先度：高 状態：完了 2026-10-07

完了 2026-10-07

開発用の yat-tat-ta-dev を作って分け、両方のプロジェクトで App Check の Firestore を適用にした。実機の Debug ビルドが開発用に書くことを確かめた。TestFlight のビルド 1.0 (1) で、Release の App Attest を通って本番の Firestore に記録が入り、App Check の画面で問い合わせが「確認済み」になることも確かめた。Firebase を開発用と本番用に分ける

概要

いまの設計では Firebase のプロジェクトは1つだけで、開発中のビルドも本番の利用者と同じデータベースに書く。
リリースまでに、開発用と本番用を分け、アプリ以外からの読み書きを App Check で断る。

分けたい理由

開発中は、ルールを書き換えて試したり、アカウントの削除を何度も試したりする。本番のデータベースでそれをやると、書き間違えたルールが利用者の記録をそのまま危険にさらす。Debug ビルドは開発用、Release ビルドは本番用の GoogleService-Info.plist を読むように、ビルドの設定で切り替える形を考えている。

App Check

アプリに埋め込む Firebase の鍵は、誰でも取り出せる。他人の記録を読めないのはルールが守っているが、アプリを通さずに Firebase へ大量に問い合わせることはできてしまう。App Check（iOS では App Attest）を入れると、本物のアプリからの問い合わせだけを通せる。

優先度が高の理由
本番に利用者が入ってからでは、分ける作業そのものが記録の引っ越しになる。利用者が0人のいまが一番安い。
先送りにした理由
リリース前は利用者がいないので、1つのプロジェクトでも壊れて困る記録がない。まず1つで保存の仕組みを動かし、確かめてから分ける。
