02 / bundle identifier

あとから変えられないのは1つだけ

4つのうち3つは、ストアに出したあとでもビルド設定を変えれば済みます。Bundle Identifier は違います。App Store に一度出すと、そのアプリの ID として固定されます。変えると別のアプリ扱いになり、レビューもダウンロード数も引き継げません。

そこで、これだけは Claude が案を出して開発者に選んでもらいました。案は GitHub のユーザー名を使う io.github.… の形が本命のつもりでした。ところが開発者は、ドメイン yat-tat-ta.com を取得済みでした。

Claude の推奨案（不採用）

io.github.{GitHub ユーザー名}.yattatta

独自ドメインなしでも他人とぶつからない形。長い。

採用

com.yat-tat-ta

取得したドメインを逆さにした形。逆ドメインの慣例どおりで、ぶつかる心配もない。

  • ハイフンは Bundle Identifier に使える文字です（英数字、ハイフン、ピリオド）。
  • ウィジェットなどの拡張を足すときは com.yat-tat-ta.widget のように下にぶら下げます。

03 / minimum deployments

端末を上げるか、下限を下げるか

前回のセッションでは、テスト用アプリが iPhone 15 Pro（iOS 26.6.1）に入りませんでした。Xcode 27 の初期値の Minimum Deployments が 27.0 だったからです。端末を iOS 27 に上げれば初期値のままでも入ります。それでも下限を 26.0 に下げました。

27.0（端末を上げる）26.0 ★採用
届く人iOS 27 に上げた人だけ。27 は 2026年9月に出たばかり。iOS 26 のままの人にも届く。
使いたい機能27 の新 API も条件分岐なしで使える。Core Haptics、AVAudioEngine、SwiftUI のアニメーションはどれも 26 で使える。
テスト端末iOS を上げる作業が要る。いまの iPhone 15 Pro にそのまま入る。

差別化の中心として決めた技術（タップ、音、振動、光の同期）は、どれも 26 で足ります。27 で上げる理由は、いまのところ見当たりません。

見直す条件：iOS 27 にしかない API が、手触りの試作で欠かせないと分かったとき。

04 / location

プロジェクトは ios/ に、設定は文字で

置き場所を決める前に、もう一つ決まっていたことがあります。2026-10-05 の調査で、Claude は XcodeGen を使うと合意していました。XcodeGen は、YAML で書いた設定ファイルから .xcodeproj を生成するツールです。

これで (a)(c)(d) の設定値が、すべて ios/project.yml の1ファイルに文字で並びます。Xcode の画面を開かなくても、差分で読めて、Claude が書き換えられます。.xcodeproj は生成物なので、リポジトリには入れません。

yat-tat-ta/
├── docs/
└── ios/
    ├── project.yml          # XcodeGen の設定。コミットする
    ├── YatTatTa/            # Swift のソースとアセット
    └── YatTatTa.xcodeproj   # 生成物。.gitignore に入れる
  • リポジトリ直下に置かないのは、docs と並べたときに何のファイルか分かるようにするため。
  • ターゲット名 YatTatTa は仮です。Swift のモジュール名にハイフンは使えないので、リポジトリ名を詰めました。ホーム画面に出る名前は別の設定で、まだ決めていません。

05 / iphone only

「iPhone 専用」でも iPad には入る

前回のテスト用プロジェクトの設定を見ると、Xcode 27 の新規 App は Mac だけでなく iPad と Apple Vision Pro も対象に入っていました。

Xcode 27 の初期値

SUPPORTED_PLATFORMS = iphoneos iphonesimulator
                      macosx xros xrsimulator
TARGETED_DEVICE_FAMILY = 1,2,7

1 = iPhone、2 = iPad、7 = Vision Pro

本番

SUPPORTED_PLATFORMS = iphoneos iphonesimulator
TARGETED_DEVICE_FAMILY = 1

ほかに Mac と Vision Pro で iPhone 版を動かす設定も NO にする

これで完全に iPhone だけになる、と思いたいところです。実際には、App Store に出した iPhone 専用アプリは iPad でも入れられます。Apple の決まりで、iPad は iPhone アプリを iPhone サイズの画面のまま動かします。それを止める正規の設定はありません。iPad 向けの画面は作らない、という意味の「iPhone 専用」です。

Apple シリコンの Mac も同じように iPhone アプリを動かせます。こちらは止められるので、ビルド設定と、ストア提出時の App Store Connect の両方で外します。

06 / decisions

決めたこと

  1. 01最小対応 iOS は 26.0。
  2. 02Xcode プロジェクトは ios/ に置き、XcodeGen の project.yml で定義する。.xcodeproj はコミットしない。
  3. 03Bundle Identifier は com.yat-tat-ta（開発者が決定）。
  4. 04対応端末は iPhone のみ。Mac、iPad 向け画面、Vision Pro は対象外。
  5. 05ターゲット名は仮に YatTatTa。
