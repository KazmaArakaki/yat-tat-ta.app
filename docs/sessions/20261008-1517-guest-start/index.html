Guideline 5.1.1(v) - Legal - Privacy - Data Collection and Storage

The app requires users to register before accessing tapping/logging features. Apps may not require users to enter personal information to function, except when directly relevant to the core functionality of the app or required by law.

01 / why

ログインを一番前に置いた理由は、通らなかった

前日の記録を Firestore に移すで、最初の起動で Apple でログインしてもらい、ログインしないと叩けない作りにしました。全員の記録が必ずアカウントに残る、というのが理由です。審査で突かれることは予想していて、審査メモに「記録を機種変更で戻すため、ログインを先に置いている」と書いておきました。

それでも通らなかった。審査の人の読みでは、叩くことと記録を付けることは、アカウントがなくても成り立つ機能です。たしかに、記録を iPhone の中に置くだけなら、アカウントは要りません。アカウントが要るのは「機種を替えても戻る」ほうで、こちらはおまけの機能だ、という判断です。

名前もメールアドレスも受け取っていないのに、と言いたくはなります。ただ、ガイドラインが問題にしているのは集める中身より「登録しないと使えない」ことのほうでした。

02 / decisions

決めたこと

  • 決定　最初の起動で、何も聞かずに匿名アカウント（Firebase Authentication の匿名ログイン）を作り、すぐホームへ進む。Apple でのログインは設定シートから、好きなときに（開発者が決定、2026-10-08）。
  • 決定　Apple でログインするときは、匿名アカウントを Apple に引き継ぐ。uid が変わらないので、それまでの記録はそのまま残る（開発者が決定、2026-10-08）。
  • 決定　引き継ごうとした Apple ID に別のアカウントがあれば、Apple のほうへ切り替えるだけ。匿名で付けた記録は、確かめてから消す。合わせはしない（開発者が決定、2026-10-08）。空になった匿名アカウントは残す（下の「実機で見つかったこと」）。
  • 提案　ログイン画面はなくす。最初の起動で電波がなく匿名アカウントを作れなかったときだけ、はじめの画面を出して「もう一度」を待つ。
  • 提案　ログアウトとアカウントの削除のあとは、新しい匿名アカウントで、記録のない状態から始まる。ログイン画面へは戻らない。
  • 提案　まだ Apple でログインしていない人の設定シートには、「Appleで続ける」と「記録をすべて削除」を置く。ログアウトは置かない（匿名アカウントからログアウトすると、記録に二度と戻れない）。

03 / flow

記録の棚は、どこから来るのか

記録は users/{uid}/records に置いています。棚の名前の uid がないと、1件も書けません。ログインをやめるなら、棚はどうするのか。

端末の中にだけ記録を置き、Apple でログインしたときにサーバーへ移す手も考えました。電波がなくても始められる。ただ、置き場所が2つになり、移す処理と、その途中で失敗したときの処理が要ります。匿名ログインなら、Firebase が何も聞かずに uid を1つ割り当ててくれるので、置き場所も Firestore のルールも今のままで済みます。あとで Apple を足しても uid は同じで、記録を動かす必要がない。こちらを選びました。

引き換えに、最初の起動だけは電波が要ります。審査の人が電波のない部屋で開くことはまずないので、ここは割り切りました。

  1. 匿名アカウントを作る画面には出ない。地の色だけ
  2. →
  3. スプラッシュいまどおり
  4. →
  5. はじめての幕端末で1度
  6. →
  7. チュートリアル記録が1件もない人
  8. →
  9. ホーム

電波がなく匿名アカウントを作れなかったときだけ、1つめの箱がはじめの画面に替わります。前のログイン画面の、床で寝ているスクワットマンはそのまま使い、「もう一度」でつながると起き上がります。すでに Apple でログインしている人と、2回目からの起動は、何も変わりません。

04 / link

Apple ID に、もう記録があったら

引き継ぎは、たいていそのまま済みます。匿名アカウントに Apple の証明を足すだけで、uid も記録も残る。

済まないのは、その Apple ID がすでに別のアカウントに付いているときです。機種変更した人が新しい iPhone で何回か叩いてから、設定シートで Apple を押した、という場面がこれに当たります。Firebase は1つの Apple ID を2つのアカウントに付けられないので、どちらかを選ぶことになります。

両方の記録を合わせる手もありました。記録は UUID ごとの文書なので、重なりはしない。それでも合わせないことにしました（開発者が決定）。切り替える前に件数を出して確かめ、匿名で付けた記録を消します。

表1　設定シートで「Appleで続ける」を押したとき
その Apple ID は匿名で付けた記録どうなるか
初めて使う何件でも引き継ぐ。記録はそのまま、設定シートの欄が「Apple でログイン中」に替わる
もうアカウントがある0件確かめずに切り替える。消すものがない
もうアカウントがある1件以上「この Apple ID には、別の記録があります」と確かめる。切り替えると、匿名の記録を消し、Apple のアカウントでログインする。空になった匿名アカウントは残る。やめれば何も起きない
電波がない、Apple のシートを閉じた何件でも何も起きない。電波がなければ「つながりませんでした」と出す

消す順番は、アカウントの削除と同じく記録が先です。先に Apple のアカウントへ替わると、匿名の棚に書き込む権限がなくなり、記録が誰のものでもないまま残ります。

06 / implementation

作ったもの

保存する記録の形も、Firestore のルールも変えていません。すでにある記録を壊す変更はありません。

  1. 1. Account：ログインしていなければ匿名でログインする。状態に「作っている（starting）」「電波がなかった（offline）」を足し、isGuest を持つ
    登録しなくても叩けるようにするため。ログアウトや削除のあとも、同じ道で新しい匿名アカウントを作る。
  2. 2. Account.complete：Apple の証明で、ログインではなく引き継ぎ（link）をする。もうアカウントがあれば pendingSwitch に預けて確かめ、switchAccount で匿名の記録を消してから切り替える
    uid を変えずに記録を残すため。匿名アカウントは消さない（下の「実機で見つかったこと」）。
  3. 3. Account.deleteAccount：匿名アカウントなら、Apple の本人確認と連携の解除を飛ばす。アカウントを消せなければ、ログアウトして手放す
    匿名アカウントには Apple が付いていない。それでもアカウントは作っているので、消す道は要る。
  4. 4. 端末のキャッシュを消し終えるまで、次の棚を開かない
    ログアウトの直後に匿名アカウントができるようになり、前の人のキャッシュを消している途中に次の棚を開くおそれが出たため。前はログアウトのあと、ログイン画面で人の手を待っていたので起きなかった。
  5. 5. LoginView を StartView（はじめの画面）に作り替え、YatTatTaApp は電波がなかったときだけそれを出す。ホームにはアカウントが替わったら作り直す印（.id）を付ける
    Apple のボタンは設定シートへ移ったので、最初の画面に残る仕事は「つながるまで待つ」だけ。切り替えのとき、開いていた設定シートを前の人の記録のまま残さないため。
  6. 6. SettingsView：まだログインしていない人の欄（Appleで続ける、記録をすべて削除、切り替えの確かめ）
    Apple でのログインを、好きなときに選べるようにするため。
  7. 7. 文言を日本語と英語で11件足し、使わなくなった3件を消す。ビルド番号を 2 に上げる
    多言語の決まり事と、審査に出し直すため。

シミュレーター向けのビルドと、既存のテストは通りました。匿名ログインと Apple の引き継ぎは Firebase の設定が要るので、まだ実機で確かめていません。

07 / device

実機で見つかったこと

開発者が実機で設定シートから Apple でログインすると、「つながりませんでした。電波のあるところで、もう一度押してください。」と出ました（2026-10-08）。電波はありました。

開発者の Apple ID には、前の日のテストで作ったアカウントがすでにあります。なので引き継ぎではなく切り替えに入り、最初の作りでは、そこで匿名アカウントを消していました。Firebase はアカウントを消すのに直前（約5分以内）のログインを求めるので、ここで断られたのだろう、と最初は考えました。Apple のアカウントなら Apple でログインし直して確かめられますが、匿名アカウントにはその手がありません。

そこで、切り替えでは匿名アカウントを消さず、記録だけ消してから Apple でログインするよう直しました。空になった匿名アカウントは、どの記録とも結びつかないまま Firebase に残ります。「記録をすべて削除」も同じで、匿名アカウントを消せなければ、ログアウトして手放します。どこで止まったかが Xcode のコンソールで分かるよう、失敗ごとにログの文言も分けました。

ところが、直して試してもらっても同じ文言が出ました。分けたログが指したのは、匿名の記録を消す一歩目です。Firestore が「Missing or insufficient permissions.」と断っていて、その前に App Check のデバッグトークンの交換が 403 で失敗していました。確かめの手順でアプリを消して入れ直したため、実機のデバッグトークンが新しくなり、開発用のプロジェクトに登録されていなかった。今回の文言の原因はこちらで、Firestore への読み書きはすべて断られていました（Firebase の準備と運用に、実機でも入れ直すとトークンが変わることを足した）。

開発用のプロジェクトにトークンを登録すると、設定シートから Apple でログインできました（開発者が実機で確かめた、2026-10-08）。

匿名アカウントを消さない直しは、取り消していません。5分を過ぎると消せないのは Firebase の決まりなので、App Check が通っていても、いずれ同じところで止まります。

08 / developer

開発者にお願いすること

1 を済ませないと、最初の起動で匿名アカウントを作れず、はじめの画面で止まります。審査の人も同じところで止まります。

  1. 1　約2分

    Firebase コンソールの Authentication → Sign-in method で「匿名」を有効にする。開発用と本番用の両方（手順）。

  2. 2　約15分

    実機で確かめる。アプリを消して入れ直すとすぐ叩ける、設定から Apple で引き継ぐと記録が残る、記録のある Apple ID だと確かめが出る、ログアウトすると空のホームになる。

  3. 3　約5分

    プライバシーポリシーを Hosting に反映する（firebase/ で npx firebase-tools deploy --only hosting -P prod）。

  4. 4　約20分

    1.0 (2) をアップロードし、審査メモを差し替え、App Review への返信を送って出し直す。

09 / later

残したこと

新しい iPhone に替えた人は、空のホームから始まります。Apple でログインすれば記録が戻るのに、そのことは設定シートを開かないと分からない。しかも先に何回か叩いてしまうと、その分は切り替えで捨てることになります。どこで知らせるかは画面の判断が要るので、出し直しを優先して課題に分けました。

    機種変更した人が、Apple でログインすれば記録が戻ることに気づきにくい。優先度：中。
