01 / why

利用者の投稿を、待たずに作る

課題 share-result は、公開から2週間待ち、利用者が何を撮って貼っているかを見てから形を決める、としていました。Wordle の共有のボタンも、利用者が先に始めていた遊びを公式にしたものだったからです。

それでも、審査の結果を待つ間に作っておくことになりました（開発者の指示、2026-10-09）。公開の初日から貼れる口があれば、最初の利用者の投稿が宣伝を運びます。形を外したら、利用者が貼る物を見てから直せばいい。

02 / decisions

決めたこと

  • 決定　共有するのは今日の記録カード。筋肉確定の瞬間ではなく、叩いたあと落ち着いてから出せるもの（開発者が決定、2026-10-09）。
  • 決定　画像だけ。動画は作らない（開発者が決定、2026-10-09）。
  • 提案　入口は今日の記録のシートの左上。1度も叩いていない人には出さない。
  • 提案　カードはいつも同じ形。連続日数を主役に、7日分のマス目、今日と DPW のドパを載せる。4:5 の縦長（1080 × 1350）で、画面の色の設定によらず明るい色で描く。
  • 提案　画像に添える文は「Yat Tat Ta でN日連続。食べたら、しゃがんで、叩く。」と公開ページの URL。体への効果も、パチンコの語も入れない（SNS の決まり事の1と2）。

03 / card

カードの形

  • 連続日数：いちばん大きく。続けた日数は、見た人がすぐ比べられる数で、毎日貼る理由にもなる。横にしゃがんだ金のスクワットマン。
  • 7日分のマス目：叩いた日はピンク、休み券でつないだ日は青（アプリの休み券と同じ色）、叩かなかった日は空。今日のマスだけ黒い枠。Wordle のマス目のように、数字を読まなくても形で分かる。
  • 今日と DPW：ドパの数だけを出す。何回しゃがんだかは、カードを見る人には要らない。
  • 下の行：はじめての幕と同じ3つの言葉と、公開ページの URL。App Store の URL は公開まで決まらないので、公開ページから App Store へつなぐ。

見本は、13日続けた人の画像をテストの中で書き出したもの（木曜は休み券でつないだ日）。最初に描いたときは下に大きな余白が残ったので、連続日数とスクワットマンを大きくし、マス目の下に曜日を足した。

04 / rules

課題に書いてあった3つの確かめ

表1　確かめたこと
確かめること結果理由
年齢制限の答え変えないApple の定義（2026-10-09 に読んだ）では、ユーザー生成コンテンツは利用者の作った物をアプリの一部として広く配ること、メッセージとチャットはアプリの中で利用者どうしがやりとりすること。共有シートで他のアプリに画像を渡すだけなので、どちらにも当たらない
画像の文言決まり事の1と2に沿う載せるのは日数、ドパ、マス目、3つの言葉だけ。体への効果も、パチンコの語もない
サーバー何も送らない画像は端末の中で作り、共有シートに渡すだけ。プライバシーポリシーは変えない

05 / implementation

作ったもの

  1. 1. ShareCard：カードに載せる数を、Ledger と日ごとの合計から作る。AppModel.shareCard で取り出す
    マス目の色分け（叩いた日、休み券の日、空の日）を、絵と切り離してテストできるようにするため。
  2. 2. ShareCardView：カードの絵と、ImageRenderer で3倍の画像にする関数
    端末の中で画像にするため。色はいつも明るいほうに固定する。暗い画面のまま貼られると、ほかの人の画面では沈んで見える。
  3. 3. TodayRecordsView：左上に共有のボタン（ShareLink）。シートを開いたときと、記録を消したときに画像を作り直す
    iOS の共有シートなら、X、LINE、インスタのストーリー、写真への保存が、何も作らずにそろう。
  4. 4. テストを3つ足す。文言を日本語と英語で2件足す
    マス目の並びと今日のドパ、休み券の日、今日まだ叩いていない日。テストは全部で98件、すべて通った。
