SNS で売る事例の調査

開発者の注文

リリースに並行してマーケティングも進めたい。SNS を使った個人開発アプリの成功事例と失敗事例を調べて、まとめる

1.0 (1) を App Store の審査に出したところ（前回のセッション）。公開は手動なので、通ったあとの公開日はこちらで選べる。

01 / question

一度バズれば、あとは回る？

個人開発のアプリが X で跳ねた話は、毎週のように流れてきます。ドパ〇〇の波も、9月下旬に X で起きたばかりです。1本の投稿が当たれば、あとはランキングが客を連れてくる。そう思いたくなります。

ところが、数字を残した人の記録は逆を向いていました。日記アプリのよりしろは、X の告知1本で1日600DL を取り、1週間後には7DL に戻っています。Product Hunt でその日の1位を取った AutoRepurpose は、2週間後の月の売上が0ドルでした。

跳ねること自体は起きる。続かないのです。だから調べたかったのは、続く流入を作った人が何を繰り返していたか、のほうでした。

02 / cases

集めた事例

成功10件、失敗8件。規模は1人か、2〜3人までに絞りました。★は Yat Tat Ta にいちばん近い2件です。

成功

  • よりしろ：X の告知1本で600DL/日
  • IsTalk：85%が TikTok か友達の紹介から
  • ねこあつめ：遊ぶとスクリーンショットになる
  • Wordle：利用者の共有の形を、ボタンにした
  • Pushscroll ★：運動 × スマホ。自分で撮った縦動画で4,000万再生
  • Wayk ★：隣のアプリの型を借り、30日で2,500万再生
  • ほか ポルン、Flappy Bird、Locket、Puff Count と HabitKit

失敗

  • バズは1週間で戻る
  • Product Hunt で上位でも、客が来ない（4件）
  • インフルエンサーに先に払って空振り
  • 検索広告は1DL 4.36ドル
  • Reddit で連投して永久 BAN
  • ほか 見ている人が客ではない、出しても DL が0、ステマで処分

事例

SNS の事例18件

1件ずつ、やったこと、数字、効いた理由、出典。未確認のものと、出典で数字が食い違うものの表。

03 / patterns

続いた人が繰り返していたこと

続いた事例に、1本の神投稿はありません。あったのは、同じ型の縦動画を何十本、何百本と出し続けたことです。Puff Count は数百本。Pushscroll は、当たった型を効かなくなるまで繰り返しました。Wayk に至っては、型を Pushscroll から借りています。

その型も、驚くほど似ていました。最初の1〜2秒のフックで問いを投げ、7〜10秒以内にアプリが動くところを見せる。撮り方は荒くていい。Wayk の人たちは「クリエイティブであろうとするのをやめた」と言っています。

効いた

  1. 使った結果が、そのまま投稿できる絵になる（ねこあつめ、Wordle、IsTalk）
  2. 3語で言えて、撮るだけで伝わる（腕立て → スクロール）
  3. 本人が撮った荒い縦動画を、同じ型で出し続ける
  4. 他人が動画にしてくれる（Flappy Bird、HabitKit）
  5. ストアの土台。スクリーンショットの直しで DL の割合が 24.2% → 37.5%（IsTalk）

失敗した

  1. ローンチの1日に賭けて、翌週の手がない
  2. 開発者仲間を客と取り違える（Product Hunt、ビルド・イン・パブリック）
  3. 型が見つかる前に、広告やインフルエンサーにお金を使う
  4. 場の決まりを無視して宣伝を連投する（Reddit）
  5. そもそも撮っても絵にならない、定番の劣化版

04 / fit

Yat Tat Ta に当てはめると

いちばん近いのは Pushscroll と Wayk です。どちらも、地味な運動に、画面の側の大きな見返りを付けたアプリでした。Yat Tat Ta なら「スクワット20回、叩くとこうなる」。3語には収まりませんが、撮れば一瞬で伝わります。CHANCE、激熱、FEVER、最後の筋肉確定。演出そのものが、7秒以内に見せる山になる。

逆に、足りないものも2つ見えました。

1つは、使った結果を外に出す口です。ねこあつめや Wordle のように、利用者が自分で投稿したくなる画面が、いまのアプリにはありません。年齢制限の答えで「ソーシャルメディアなし」と答えた作りなので、足すなら次の版です。課題に積みました。

もう1つは値段です。集めた事例は、ほとんどが無料で入れてサブスクで払う形でした。US$0.99 の買い切りは、動画から来た人の前に「払う」壁を1枚置きます。この壁を越えるかどうかは、事例からは確かめられませんでした。ストアのスクリーンショットとプレビュー動画で、演出を先に見せきるしかない。いまの6枚が、その役を担えるかは、出してから数字で見ます。

05 / proposals

提案

決定は1つ（動画の主役）。残りは提案で、下の「開発者に決めてほしいこと」の答えで変わります。

  • 提案　主な場所は縦動画（TikTok、YouTube Shorts、Instagram Reels）。同じ1本を3か所に出す。X は、公開日の告知と、ドパ〇〇の流れに乗る1本に使う。X だけに頼ると、よりしろと同じく1週間で戻る。
    → 開発者の判断で、まず X の日本語から始める（2026-10-07）。縦型動画の場所を広げるのは、X で当たる型が見えてから。
  • 決定　動画の主役はスクワットマン。開発者は映らない。AI で作った人も使わない（開発者が決定、2026-10-07）。アプリに入っている本物の素材なので、作り物の映像を映さないという決まりに触れず、AI 生成の表示も要らない。画面は、スクリーンショットと同じ演出の見本（-demo、-seed）をシミュレーターで録画すれば、叩かずに FEVER も筋肉確定も何度でも撮れる。
    型は1つから始める。1〜2秒め「食後のスクワット20回、地味すぎる」→ スクワットマンがしゃがむ → 叩き始めた画面 → 7秒以内に FEVER か筋肉確定。事例で効いていた本物の人のリアクションは無いので、掴みは声と演出の騒がしさで作る。最初の5本ほどの再生の落ち方を見て、型を直す。
  • 提案　開発者が毎食後スクワットを続ける連載にする。映るのはスクワットマンと画面だけで、日数と回数は開発者の本物の記録を使う。1日1本、連続記録の日数をそのまま題に入れる。ネタを毎回考えなくて済む形にしておかないと、ポルンのように投稿が重くなる。
  • 提案　広告とインフルエンサーには、自分の動画で当たる型が見つかるまでお金を使わない。US$0.99 では、1DL に4ドルの広告は割に合わない。
  • 提案　発信の決まり事（健康効果の言い方、ステマ規制、レビューの頼み方）はSNS で発信するときの決まり事にまとめた。投稿の前に開く。

07 / sample

見本の動画を1本作る

投稿の自動化を決める前に、1本を作って型を目で確かめることにしました（開発者の依頼、2026-10-07）。

シミュレーターでは連打できません。スクリーンショットのときと同じく、演出の見本に叩かせます。ただ、今回は止まった1枚ではなく、1打めからフィナーレまでの流れが要る。そこで、時間をかけて叩き続ける見本 reel を足しました。

もう1つの壁は音でした。シミュレーターの画面の録画には、音が入りません。演出の半分は声なので、音のない動画では掴みが作れない。アプリが鳴らした音を、そのままファイルにも書く口（-recordAudio）を足し、録画とあとで重ねます。

  1. 1. 演出の見本 -demo reel
    1.5秒待ってスクワットマンを起こし、0.3秒おきに20回叩く。6打めでフィーバーを当て、5秒の間は0.11秒おきに叩く。フィナーレが消えたら、音の始まりの時刻を Documents の reel.json に書いて終わる。Debug のビルドにだけ入る。
  2. 2. 鳴らした音をファイルに書く FeelEngine.startRecording
    音はすべて AVAudioEngine の1つのミキサーを通るので、そこで聞き取って Documents の reel.caf に書く。Debug のビルドにだけ入る。
  3. 3. ios/Design/reel.sh
    ビルド、録画、音を重ねる、掴みの文字を入れる、1080 × 1920 に整える、までを1本のスクリプトで。録画の始まりとアプリの音の始まりは、Mac の時計の時刻で合わせる。できあがりは ios/Design/Reels/reel-ja.mp4（Git には入れない）。
  • 1本めを作った（2026-10-07）。19秒。0〜3秒に掴みの文字「食後のスクワット20回、地味すぎる。」、約4秒で FEVER、約13秒で筋肉確定、最後にねぎらい。音は入っている（平均 −12.4 dB）。
  • 掴みの文字は、連続記録の帯と残りの回数の上にかぶる。最初の3秒だけなので、そのままにした。
  • アプリの画面は縦に長い（1206 × 2622）ので、1920 の高さに合わせると左右に紙の色の余白が出る。
  • 保存している記録には触れない。見本の記録（-seed）はメモリだけで開く。

開発者が見て「そもそも訴求になっていない」と判断した（2026-10-07）。X では動画が無音で自動再生され、声の演出が消える。何のアプリかも、叩いていることも、画面からは分からない。最初に狙う場所を X の日本語に絞り、型から調べ直した。

調査

X の縦型動画のグッドとバッド

見本の1本の4つの穴、X のおすすめ欄の重み、日本の個人開発の投稿6件、次の1本の本文と動画の流れの案。
  • 2本めを、調べた型で作り直した（開発者の依頼、2026-10-07）。24秒。上の帯に場面ごとの文字（スクワット、終わった？ → 1回＝1打 → 叩くたびに、どんどん派手に → FEVER！5秒間、叩き放題 → 最後の1打で、筋肉確定。）、約10秒で FEVER、約16秒で筋肉確定、最後の2.5秒にアイコンとアプリ名。
  • 叩いた場所に指の印（白い丸）を出す。AppModel.demoTouch を見本のときだけ立て、ホームの一番上に描く。Debug のビルドにだけ入る。
  • 叩く間隔を 0.6秒から 0.28秒へ詰め、勢いが付いていくように見せる。フィーバーは激熱のあとの14打めに移した。
  • 文字は帯の中にだけ出し、アプリの画面にかぶせない（1本めの穴）。帯の文字を出す時刻は、アプリが reel.json に書く場面の時刻（最初の1打、CHANCE、FEVER など）から決める。組み立ては ios/Design/compose_reel.py。
  • 終わりの画面のアイコンは、AppIcon.icon の SVG を Quick Look で PNG にしてから重ねる。ImageMagick だけでは人形の線が描けなかった。
  • 左右の白い余白を、スクワットマンの隊列で埋めた（開発者の依頼、2026-10-07）。片側に2列、26人ずつ。起こすまでは寝ていて、叩き始めると1.2秒に1回しゃがみ、フィーバーの間は0.4秒に1回になる。少しずつ遅れて動き、波のように見える。右の隊列は反転して、画面のほうを向く。
  • 隊列の絵は ios/Design/reel_squad.swift が CoreGraphics で描く。関節の位置と色はアプリの SquatterLayer と同じ点をそのまま写した。アプリの人形を直したら、ここも直す。
  • 決定　開発者が見本の動画を OK とした。投稿は、アプリ専用の新しい X のアカウントから出す（開発者が決定、2026-10-07）。プロフィールの文、アイコン、ヘッダーは発信の決まり事に置いた。最初の投稿は、App Store のリンクが貼れる公開日まで取っておく。
  • 開発者がアカウント @yattattadotcom を作った。名前は「スクワットアプリ【Yat Tat Ta】広報兼サポート担当」（2026-10-07）。
