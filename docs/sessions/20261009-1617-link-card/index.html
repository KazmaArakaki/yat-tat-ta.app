LINE と X にリンクカードを出す

開発者の注文

共有ボタンを３つに分けたい。
「LINEで共有する」「Xで共有する」
「他の方法で共有する」

01 / why

LINE と X には、画像を渡せない

ボタンを分けるだけなら簡単だ、と最初は思いました。ところが、アプリから LINE や X の投稿画面を直接開くとき、渡せるのは文と URL だけです。X の投稿画面を開く口（x.com/intent/post）も、LINE の共有の口（line.me/R/share）も、画像を受け取りません。画像ごと渡せるのは iOS の共有シートだけで、共有シートは相手のアプリを先に選んでおけない。

カードの画像は端末の中にしかないので、URL から読ませることもできません。開発者とやりとりして、カードの数字だけをサーバーに送り、サーバーが描いたカードを URL の リンクカード（OGP 画像）として出す形に決めました（開発者と合意、2026-10-09）。前のセッションまでの「サーバーには何も送らない」は、LINE と X に限って変わります。

02 / flow

押してから、カードが出るまで

  1. 1. 利用者が「Xで共有する」か「LINEで共有する」を押す。
  2. 2. アプリは、ログインのトークンと App Check を付けて、カードの数字（日付、連続日数、7マス、今日のドパ、DPW、言語）を関数 createShareCard に送る。
  3. 3. 関数は値の範囲を確かめ、横長のカードを描いて Cloud Storage の share/[ハッシュ].png に置き、https://yat-tat-ta.web.app/s/[ハッシュ] を返す。同じ見た目なら同じハッシュで、2度は描かない。
  4. 4. アプリは、文とその URL を入れて X か LINE の投稿画面を開く。開けたら、今日は共有したことにする。
  5. 5. X や LINE のクローラーが /s/[ハッシュ] を読みに来る。関数 share が、OGP のメタタグを入れた HTML を返す。
  6. 6. クローラーが /s/[ハッシュ].png を読みに来る。置いてある画像をそのまま返す。どちらも CDN が1年覚えるので、関数が動くのはほぼ1回。
  7. 7. タイムラインやトークに、文と大きなカードが並ぶ。人がカードを押すと、同じ HTML の JavaScript が LP（英語なら /en/）へ移す。

押したあとに移すのが LP だけなのは、開発者の提案です。見た人は押す前にカードを見ているので、もう一度見せるより、何のアプリかを見せるほうがいい。HTTP のリダイレクトにしないのは、クローラーまで LP に移って、LP の OGP が出てしまうからです。

03 / images

リンクカードと、3つのボタン

リンクカードは横長（1200 × 630）です。X と LINE のリンクカードがこの比率なので、アプリの縦長のカード（4:5）を横に組み直しました。描くのはサーバーの satori と resvg で、文字はドキュメントでも使っている M PLUS Rounded 1c（OFL）を、使う文字だけに絞って関数に入れています。最初に描いたとき、3桁の日数が枠からはみ出し、ロゴの語の間が開きすぎたので、桁数で文字を小さくし、語の間を自分で決めました。

「他の方法で共有する」は今までどおり、共有シートで縦長の画像ごと渡します。LINE と X でも、電波がないときや関数が失敗したときは、この形に切り替えます。

04 / decisions

決めたこと

  • 決定　共有のボタンは「LINEで共有する」「Xで共有する」「他の方法で共有する」の3つ（開発者が決定、2026-10-09）。
  • 決定　先に画像を作って URL を返し、その URL を共有する（開発者の案、2026-10-09）。共有する URL は画像ではなく HTML のページにする。X は画像の URL からリンクカードを作らない。
  • 決定　画像はサーバーで描き、アプリからは受け取らない。任意の画像を上げられると、こちらが利用者の画像を公開する形になり、悪用の口にもなる（開発者と合意、2026-10-09）。
  • 決定　数字はアプリの申告を信じ、ありえない値だけを断る。サーバーで記録から計算し直すと、連続記録の計算を2つ持つことになる（開発者と合意、2026-10-09）。
  • 決定　作った画像は消さない。消すと過去の投稿のカードが出なくなる（開発者と合意、2026-10-09）。
  • 決定　カードを押したら LP へ移すだけ（開発者の提案、2026-10-09）。
  • 提案　関数は、ログイン中（匿名を含む）で App Check の通ったアプリからだけ受け付ける。uid は確かめるのに使うだけで、画像にもどこにも残さない。
  • 提案　LINE と X は、投稿画面を開けたら今日は共有したことにする。投稿したかまでは分からない。

05 / implementation

作ったもの

  1. 1. firebase/functions/src/card.js：数字の確かめ（normalize）、ハッシュ、横長のカードの描画
    関数の入口から切り離し、手元でテストできるようにした。
  2. 2. firebase/functions/src/page.js：/s/[ハッシュ] の HTML
    OGP のメタタグと、人だけを LP へ移す1行。埋める値は逃がす。
  3. 3. firebase/functions/src/index.js：createShareCard（onCall）と share（onRequest）。firebase.json に関数、/s/** の振り分け、Storage のルールを足す
    Storage はアプリから直接触らせない。書くのも読むのも関数だけ。
  4. 4. iOS：ShareService（3つの道と、失敗したときの共有シート）、SharePromptCard を3つのボタンに、今日の記録のシートの共有をメニューに。project.yml に FirebaseFunctions
    リンクカードを作る1、2秒は、押したボタンに回る印を出し、ほかを押せなくする。
  5. 5. テスト：関数側に8つ（値の確かめ、ハッシュ、PNG の大きさ、HTML）、iOS に3つ（送る数字、X と LINE の URL）。文言を日本語と英語で4件足し、使わなくなった2件を消す
    iOS のテストは全部で107件、すべて通った。

07 / device

開発用に出して、触ってみて

開発用（yat-tat-ta-dev）を Blaze に上げ、予算のアラートと、Cloud Run Functions の利用額上限を付けました。上限に届くと、その月の残りは関数が止まります。LINE と X のボタンは共有シートに切り替わるので、共有そのものは止まりません。Storage の既定のバケットは asia-northeast1 に作りました。米国の3リージョン以外には無料枠がありませんが、画像1枚がおよそ50KBなので、保管料は月に数円の見込みです。

最初のデプロイは終了コード 1 で止まりました。関数は2つとも作れていたのに、古いコンテナイメージを消す設定（cleanup policy）を作れずに終わり、Hosting の新しい版が公開されないまま残った。/s/ は 404 を返していました。--force を付けて出し直すと、イメージを1日で消す設定が入り、Hosting も公開されました。

そのあと curl で振り分けを確かめました。知らないハッシュの /s/[ハッシュ] は関数まで届いて LP へ 302、.png は 404。Hosting の trailingSlash: true で、スラッシュ付きの URL へ移されることもありませんでした。

X での共有を試すと、X アプリの中のブラウザが立ち上がりました（開発者が実機で確かめた、2026-10-09）。x.com/intent/post は X アプリに渡らず、アプリの中のブラウザで開く。そこでは X にログインしていないので、投稿できません。X アプリの投稿画面を直接開く URL スキーム（twitter://post?message=）を先に試し、X アプリが入っていないときだけ Web の投稿口を開くようにしました。この口は文と URL を分けて受け取れないので、URL は文の最後に付けます。

直したあと、X アプリの投稿画面が開き、投稿すると横長のカードが出て、押すと LP に移りました。LINE でも、送った URL にカードが出ました（開発者が実機で確かめた、2026-10-09。開発用の Firebase）。

本番（yat-tat-ta）も Blaze に上げ、予算のアラート、Cloud Run Functions の利用額上限、asia-northeast1 の Storage をそろえてから、--force 付きでデプロイしました（2026-10-09）。関数は2つとも作れ、/s/ の振り分けは開発用と同じ答えを返し、改定したプライバシーポリシーも公開されました。本番のリンクカードは Release のビルド（App Attest）からしか作れないので、TestFlight で確かめます。

X への共有に、ハッシュタグ #YatTatTa #食後スクワット（英語のときは #YatTatTa だけ）を付けることにしました（開発者が決定、2026-10-09）。アプリの名前のタグは、利用者が何を貼っているかを検索で拾うため。タグは文と URL の間に置き、URL を最後に残します。X は最後の URL からカードを作るからです。

  • 2回目の叩き切りで、共有の誘いが出なかった
    1回目に X か LINE のボタンを押し、投稿画面を開いていた。投稿画面が開いたら、その日は共有したと数えるので、作りどおり。投稿したかまでは、アプリからは分からない。
  • 今日の記録のシートの共有ボタン（左上のメニュー）が分かりづらい
    開発者の注文（2026-10-09）で、シートのいちばん上に見出し「今日の記録を貼る」と、共有の誘いと同じ3つのボタンをそのまま並べた。1度も叩いていない人には出さない。チュートリアルの記録を貼る場面の「今日の記録の左上からも」も、「今日の記録のシートからも」に直した。
