スプラッシュを作る

開発者の注文

スクワットを続けたくなるスプラッシュを

考え抜いてほしい。Apple Design Award を狙えるくらいまで。

01 / question

ロゴを見て、しゃがむ人はいない

スプラッシュと聞いて、最初に浮かんだのはロゴでした。地の色に名前を置き、少し待ってホームへ。1.5秒はそれで埋まる。

ただ、ロゴを見てスクワットをしたくなる人はいません。Apple の Human Interface Guidelines も、起動の画面を広告に使うなと書いています。起動の一瞬に置いてよいのは、使う人にとって意味のあるものだけです。

毎食後にこのアプリを開く人にとって、意味のあるものは何か。答えはホームの左上にもう出ていました。「29日連続」。けれど、あそこにあるのは 44pt の数字が1つだけです。29日ぶんの重みは、数字1つでは伝わらない。

02 / concept

29人の隊列と、空いた席

29日を29人で見せます。スクワット隊と同じ人形を1日に1人、曜日にそろえて並べる。1行が1週間で、休み券を使った日には青い札が入ります。

隊列は、古い日から順に1回ずつしゃがむ。波は0.55秒で今日まで流れ、最後の1か所で止まります。そこだけ人形がいない。床の印に上から光だけが差している。今日の席です。

  1. 01 積み上げが人数で見える

    数字の29は読み流せても、29人の隊列は読み流せない。ここで手放すには惜しい量だと、目で分かります。

  2. 02 空いた席は埋めたくなる

    並びの最後が1つだけ欠けていると、人はそこを閉じたくなる。「今日まだ」を、責める文を1行も書かずに伝えられます。

  3. 03 名前が3拍で言い切る

    Yat Tat Ta は「やったった」。1語ずつ落ちてつぶれる3回が隊列の波と重なり、3拍めの「Ta」で波が今日の席に届く。名前の意味が、説明なしで手に入ります。

  4. 04 幕とホームのつなぎ目がない

    最後に大きな数だけが飛び、連続記録の帯の数になる。スプラッシュで見た29が、ホームで叩く理由のまま残ります。

ロゴは、どこにも出てきません。名前の3語がその代わりをします。

03 / intro

はじめての1回は、やって見せる

最初の案では、はじめての起動は今日の席が1つあるだけでした。並べる日がないのだから、席1つで足りる。そう考えていた。

開発者のレビューは「初めての時はもっと丁寧に、これからスクワットすることに対する期待感を持たせるように」。読み返すと、席1つの画面は、まだ何も始めていない人に「ここが空いています」と言っているだけでした。何で埋まるのか、埋めると何が起きるのかは、どこにも書いていない。

そこで、はじめての1回だけは14.0秒のはじめての幕にします。中身は3つの場面です。

  1. 2.6秒〜 やって見せる

    大きな人形が1人、「食べたら、」で立ち、「しゃがんで、」でゆっくりしゃがみ、「叩く。」で足元からドパの粒が出る。毎日やることの全部が、1人の動きに入っている。

  2. 7.0秒〜 来週を先に見せる

    その人形が縮んで、今週の隊列の左端の席に入る。右に明日からの席と休み券の札。明日からの6人が1人ずつ立って、いっしょに消える。1週間続けた自分たちの姿を、始める前に見る。

  3. 11.0秒〜 1人目を指す

    ほかの席が引き、今日の席だけが大きく残る。「最初の1回で1日目」「1人目は、今日のあなたです。」

2回めのレビューは「もっと丁寧に。一呼吸おいて。」でした。6.0秒の版を見返すと、場面と場面が切れ目なくつながっていた。名前が落ちきる前に人形が立ち、人形が縮む前に席が並ぶ。全部が見えているのに、どれも眺める時間がない。

そこで、場面のあいだに間を入れて、14.0秒にしました。足したのは動きではなく、何も起きない時間です。

  • 始まる前に0.6秒。地の色だけを見せてから、名前を落とす。
  • 名前を眺める1.2秒。3語が落ちきったあと、何も動かさない。
  • 言葉は1つずつ。「食べたら、」「しゃがんで、」「叩く。」を1行に並べず、前の言葉が消えてから次を出す。
  • しゃがみは1.4秒。下りて、とどまって、上る。ふつうのスクワットの速さに近づけた。
  • 叩いたあとに0.4秒。言葉が消え、人形だけが立っている。ここで最初の場面が終わる。
  • 「1日目」と「1人目」のあいだに0.6秒。数を読んでから、一言を読む。

動きの入りと止まりは、すべてゆっくりした曲線（sine）にそろえました。叩くと次の場面の頭へ進みます。一度に最後まで飛ばすと、せっかくの間を叩き1つで全部捨てることになるからです。

一瞬だけ立つ6人が、期待のいちばんの材料です。見せてすぐ消すので、手に入るものではなく、これから手に入るものとして残る。見せるのは1度きりです。

03b / seat

今日の席は、光の差す床

最初の版では、今日の席を「立った人形の点線」で描いていました。空いた場所を、いるはずの人の輪郭で示せば伝わる、と考えた。

開発者のレビューは「点線のスクワット人間が違和感あります」。並べて見直すと、点線の人形は空いた席には見えません。体が欠けた人形、幽霊のような人形に見える。隊列の中で、そこだけ別の生き物になっていた。

空いていることは、人の形ではなく、場所の形で見せることにしました。床に dopa の丸い印を置き、上から薄い光を差す。舞台に光だけが当たっていて、立つ人をまだ待っている形です。ほかの人形の足元にも薄い影を落としたので、印が「人の立つ場所」だと読めます。今日叩いたあとは、その印の上に人形が立ちます。

04 / mock

修正イメージ

状態を切り替えて再生できます。はじめての幕は「はじめての起動」のタブ。暗い配色とひかえめモードも確かめられる。枠を押すと、その場でホームへの引き継ぎに飛びます。部品ごとの見た目は ui／スプラッシュ。

05 / spec

端の場面

出すときと時刻の表は機能ページにまとめました。ここには、判断が要った場面だけを置きます。

場面決めなぜ
1日に何度も開く起動したときと、その日最初に開いたときだけ毎回出すと、2回目からはただの待ち時間になる。1日の最初の1回だけ、席が空いていることを見せる
今日もう叩いた出す。今日の席には人形が立っていて、波が届くと2回しゃがむ。一言は「✓ 今日のぶんは済み」済んだ日も、積み上げは見たい。急かすことは何も言わない
はじめての起動はじめての幕（14.0秒）を1度だけ。見せたことを端末の設定 introShown に残す開発者のレビュー。何をするアプリかと、続けると何が起きるかを、始める前に見せる
はじめての幕のあと、まだ叩いていないふつうの幕。隊列なしで今日の席だけを大きく、「最初の1回で1日目」やって見せるのは1度で足りる。2度目からの14秒は待ち時間
途切れたあと前の連続の人形は並べない。今日の席だけを大きく出し、一言は最長記録灰色の人形を並べれば、欠けた列が先に目に入る（文言の決まり）
100日を超える8週を超えたら、古い週を「＋N日」にまとめる。波の長さは0.55秒のまま12週まで並べると、人形が点にしか見えなかった（見本で確かめた）。人数が多いほど、波は速く走って見える
次の1回で節目一言の横に gold の「節目」の札あと1回で何が起きるかを、起動した瞬間に見せる
早く叩きたいどこを叩いても引き継ぎ（最後の0.4秒）へ飛ぶ。その1打は数えない見ていない1打を記録に混ぜない
ほかの重ね物途切れたときのカードと休み券の帯は、スプラッシュが消えてから出すどちらも「最初に開いたとき」に出るので、必ずぶつかる
ひかえめモード落下、波、輪、飛ぶ数をやめる。置いたまま0.9秒、0.25秒で溶かす。振動の3拍は変えないひかえめモードの決まり。音と振動は変えない
VoiceOver幕全体を1つの要素にし、「Yat Tat Ta。29日連続。今日の1回で30日目。」と読む。読み終わるまで幕を残す隊列の形は聞いても分からない。1.65秒で切ると、読み上げが途中で消える
起動画面iOS が出す起動画面の地を、paper（暗い配色では #16120F）にするいまは白（暗い配色では黒）。スプラッシュの地と色が違うと、切り替わる瞬間にちらつく

06 / award

賞の6部門に当ててみる

Apple Design Award は、6つの部門で選ばれます。この幕で届くところと、届かないところを分けました。

部門この幕で効くところ手当て
Delight and Fun名前を踏む3拍、古い日から流れる波毎日見ると飽きる。だから1日1回に絞った
Inclusivityひかえめモード、VoiceOver の1文、音を出さないこと今日の席は色ではなく形（人形のいない床の印と光）で分かる。dopa と gold の見分けがつかなくても読める
Interactionどこを叩いても飛ばせる。数が帯まで飛ぶ飛ばした1打を数えない
Visuals and Graphics隊、履歴と同じ人形。起動画面と同じ地新しい絵柄を足さない
Innovation／Social Impactこの幕だけでは決まらない賞はアプリ全体に贈られる。幕は、毎食後スクワットという題材の入口として働けば足りる

07 / rejected

選ばなかった案

  • 起動の声「やったった」を鳴らす。声の音源はもうあります（voice_yattatta）。ただ、開くのは食事のあと。店の中で起動の声が鳴ると、次から開かなくなる。
  • 途切れた日を灰色の人形で並べる。形としてはきれいでした。けれど、最初に目に入るのが欠けた場所になる。
  • DPW や DT も並べる。1.65秒で読める数は1つまで。ほかの数はホームのカードで読める。
  • 今日の席から隊がステージへ歩いて行く。ホームの隊は寝ていて、長押しで起こす決まり。立って歩いて来た隊が寝直すのは、話がねじれる。

08 / detail

作る場所

所要はあわせて6〜7時間（はじめての幕で2時間増えた）。数を帯の位置へ飛ばす引き継ぎと、人形を今日の席へ縮めて入れる動きが、読めないところです。記録の保存の形は変わりません。端末の設定に introShown を1つ足します。

場所変更なぜ
Model/Lineup.swift（新規）Ledger.Streak と今日と週の始まり（Calendar.firstWeekday）から、隊列のマスを作る。マスは「人形」「休み券」「今日の席」「今日済み」「空き」。8週を超えたぶんの日数も返す並べ方を画面から切り離し、テストで確かめる。Ledger と同じく保存しない
History/SquatFigure.swift人形を描く処理を、Canvas の中から呼べる静的な関数に切り出す隊列の数十人を1枚の Canvas で描く。履歴の人形と同じ形のまま
Home/SplashOverlay.swift（新規）名前、隊列、数と一言。TimelineView の時刻から、拍、波、輪、引き継ぎを描く。叩くと引き継ぎへ飛ぶ。VoiceOver では1つの要素時刻を1つの表（T）に集め、見本の splash.js と同じ秒にそろえる
Home/IntroSplash.swift（新規）はじめての幕。大きな人形のやって見せる動き、今週の7つの席、明日からの6人、今日の席への寄せ。時刻は表 INTRO に集める。1回叩くごとに次の場面の頭へふつうの幕と場面の数が違うので、別の View にする。人形の描き方、席、引き継ぎは SplashOverlay と共有
Mash/Settings.swiftSettingKey.introShown（Bool）を足す。はじめての幕を出し始めたときに true1度きりにするため。消えても、もう1度はじめての幕が出るだけ
Home/StreakBar.swift日数の数字の位置を anchorPreference で上へ渡す。スプラッシュが飛んでいるあいだは数字を隠す飛ぶ先を、帯の実際の位置から決める。端末の大きさが違っても同じ所に着く
HomeView、AppModelスプラッシュを出すかどうか（起動したとき、記録日が変わって戻ったとき、叩いている最中でないとき）。途切れたときのカードと休み券の帯は、幕が消えてから重ね物の順番をホームの1か所で決める
Feel/FeelEngine.swift振動の3拍（0.15秒 弱、0.45秒 弱、0.75秒 中）を1つの CHHapticPattern で鳴らす。はじめての幕は、名前の3拍と「叩く」「今日の席」の5つ1つの模様にすれば、絵と振動がずれない
Assets、Info.plist色 LaunchBackground（paper と #16120F）を足し、UILaunchScreen の UIColorName に指定する起動画面からスプラッシュへ、色を変えずにつなぐ
Localizable.xcstrings「＋%lld日」と VoiceOver の1文。はじめての幕の「食べたら、」「しゃがんで、」「叩く。」「1日1回で、1人ずつ。」「来週には、7人の隊になる。」「1人目は、今日のあなたです。」。英語も同時に。ほかの文は帯と同じものを使う多言語の決まり事
テストLineup：曜日のそろえ方、休み券の日、今日済み、途切れたあと、はじめて、8週を超えたとき動きはシミュレーターで見るしかないが、並び方は機械で確かめられる
docs実装でずれたところを、機能、部品の見本、用語に戻す。UI の基本方針の「重ねる部品」にスプラッシュを足す見本と実物をそろえておく

09 / review

見てほしいところ

注文にない数と振る舞いを、こちらで決めました。1回めと2回めのレビュー（2026-10-07）で、はじめての起動をやり直しています（03 / intro）。3回めのレビューで、今日の席の形を替えました（03b / seat）。開発者は、ここまでの形でよいとした（2026-10-07）。

  1. 出すのは、起動したときと、その日最初に開いたときだけ。起動するたびに必ず、のほうが分かりやすくはあります。
  2. 音は出さない。声の「やったった」を鳴らす案は捨てました。振動の3拍だけです。
  3. 長さは1.65秒。波と3拍を見せるのに要る最短です。叩けば0.4秒で終わる。
  4. 途切れたあとは、前の隊列を見せない。最長記録の数だけを一言に出します。
  5. 隊列は8週まで。それより前は「＋N日」の札1枚にまとめます。
  6. はじめての幕は14.0秒、1度きり。場面ごとの間（0.4〜0.6秒）を足したぶん長くなりました。叩くたびに次の場面へ進むので、急ぐ人は数回でホームへ移れます。

10 / decisions

決めたこと

  1. 01スプラッシュはロゴではなく、いまの連続の日を人形で並べた隊列と、今日の席を見せる。
  2. 02名前の3拍と隊列の波を重ね、3拍めで今日の席に届く。振動も3拍。
  3. 03最後は大きな数だけが連続記録の帯へ飛んで、ホームに引き継ぐ。
  4. 04ホームの上に重ねる部品にする。画面は増やさない。保存の形（SquatRecord）は変えない。
  5. 05はじめての起動は、これからスクワットすることへの期待を持たせるよう丁寧に（開発者のレビュー）。1人の人形でやって見せ、今週の席と明日からの6人を見せる、はじめての幕にする。
  6. 06はじめての幕は、場面ごとに一呼吸おいて14.0秒にする。言葉は1つずつ。叩くと次の場面へ進む（開発者のレビュー「もっと丁寧に。一呼吸おいて。」）。
  7. 07今日の席は、点線の人形ではなく、人形のいない床の印に光が差す形にする（開発者のレビュー「点線のスクワット人間が違和感あります」）。

12 / build

作ったところ

テストは69件すべて通った。足したのは Lineup の8件で、今日の席が今日の曜日の列に来ること（日曜始まりと月曜始まり）、今日済みの人形、休み券の日を挟むこと、連続より古い休み券を並べないこと、途切れたあととはじめては今日の席だけ、29日で5週、100日で8週にまとめること。 シミュレーター（iPhone 17）では、ふつうの幕、30日分の隊列（-perf -demo splash）、はじめての幕の場面ごと、暗い配色を、秒を止めて確かめた。入れ直して起動すると、はじめての幕が出て14秒でホームに移り、開き直すとふつうの幕になることも確かめた。 振動の3拍と、叩いて飛ばす手触り（はじめての幕では1回ごとに次の場面へ）は、開発者が実機で触って OK とした（2026-10-07）。

  • スプラッシュは HomeView のいちばん上に重ねる。AppModel.splash があるあいだ、休み券の帯、途切れたときのカード、通知の問いかけは出さない。
  • 出すかどうかは AppModel.presentSplashIfNeeded。起動したとき（App の init、最初の1枚から重ねる）と、戻ってきたときに呼び、記録日が前に出した日と同じなら出さない。
  • はじめての幕は、introShown が立っていなくて、記録が1件もないときだけ。前から使っている人には、introShown を立てるだけで、ふつうの幕を出す。
  • 数の飛ぶ先は、帯の数字が onGeometryChange で知らせる画面上の位置。幕の数は置き場所だけを取り、見える数を上に重ねて飛ばす（飛ぶ動きで測る位置がずれないように）。
  • 人形の描き方は SquatFigure.draw に切り出し、履歴の人形と隊列とで共有した。起動画面の地は色 LaunchBackground（Info.plist の UILaunchScreen）。
  • 見た目の確認用に、起動引数 -demo splash、-demo intro、-splashAt 秒 を足した（iOS プロジェクト）。
  • 文言12件に英語を入れ、訳語表に足した。
