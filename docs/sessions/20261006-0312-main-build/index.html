02 / position

4つの機能と、その置き場所

前回の題材を決めるで、何を数え、何を見せるかは決まりました。決まっていないのは、それをどう組むかです。並べてみると、題材は4つの機能に分かれます。どれも同じ「記録」を読み書きします。

feature / done-mash

完了連打

叩いてスクワットをドパに変える。記録を作るのはこの機能だけ。最後の1打のフィナーレもここ。

feature / dopa-totals

ドパの合計

DT と DPW を出す。DPW は前の7日と自己ベストに並べる。DT の節目を判定する。

feature / streak

連続記録と休み券

何日続いたか、休み券が何枚あるか。途切れたときに出すカードも、この機能が持つ。

feature / today-reminder

今日まだ通知

その日まだ叩いていない夜に、1回だけ知らせる。開かれなければ7日で自分から止まる。

画面は1枚にします。上に連続記録、まん中に叩くボタン、下に DPW と DT。前回のラフとほぼ同じ並びです（画面の見本は ホーム）。設定は右上の歯車から下に出すシートで、目標回数と通知だけを置きます。記録の一覧画面は作りません。取り消しを作らないと決めたので、一覧で見せて操作させるものがないからです。

03 / closing

手が止まった連打は、いつ1件になるのか

20打を叩き切れば、話は簡単です。最後の1打で残りが0になり、そこで記録が1件できる。迷うのは、7打で手が止まったときです。叩いた7ドパはその場で確定する、と前回決めました。では、残りの13はいつまで待てばいいのでしょうか。

待ちすぎると困ったことが起きます。昼に7打で止めた人が、夜食のあとに開くと、ボタンにはまだ「13」が残っている。夜のスクワット20回を叩くはずが、13打で昼の記録に足されて終わります。

手がかりは叩く順番にあります。完了連打は、スクワットを終えてから叩くものです。しゃがみながら叩くわけではないので、連打の途中で1分も手が空くのは、やめたときだけでしょう。そこで、閉じる条件を3つにしました。

閉じる 1

残りが0になった

最後の1打。フィナーレを出す。そのあと1.2秒は叩いても数えない。勢い余った指で、次の記録が始まらないように。

閉じる 2

60秒叩かなかった

叩いたところまでで1件にする。フィナーレは出さない。ボタンは目標回数に戻る。

閉じる 3

アプリを離れた

ホームに戻った、電話が来た。2 と同じ閉じ方。離れたまま終了されても、叩いた分が消えない。

途中で閉じた7打も、立派な1件です。連続記録もつながります。継続の条件は「その日に完了連打を1回」で、目標回数に届いたかは問いません。前回、条件を低くするほど続く、という Duolingo の数字を見たばかりです。

保存は、閉じたときに1回だけ行います。1打ごとに書き込むと、タップの瞬間の仕事が増えるからです。手触りの試作で、音のファイルも振動のプレイヤーも先に作っておいたのと同じ理由です。叩いている間の数は画面の中だけにあり、閉じた瞬間に端末へ書く。アプリが落ちれば、その1件は消えます。ただし落ちるのは異常なときだけで、普通に離れた場合は 3 の条件で必ず書き込まれます。

04 / effects

3つの強まりを、何で表すか

前回決めた強まりは3つでした。変換の進み具合、その日の最初の1回か、節目に届いたか。手触りの試作では、もう1つ別の強まりを使っています。0.45秒以内に叩き続けると段階が上がる、連打の速さです。開発者が「気持ちいい」と答えたのは、こちらでした。

どちらか1つに絞るなら、進み具合を取るべきだと思っていました。速さで音程を上げると、ゆっくり20打を叩く人は、最後の1打まで低い音のままになるからです。けれども速さを捨てると、試作で確かめた気持ちよさまで捨てることになる。そこで、受け持ちを分けました。

表1　1打ごとの演出と、何で強さを決めるか

出すもの強さを決めるもの理由
音の高さ、振動の強さ進み具合。目標回数を8つに割り、何打目かで8段階のどれかを鳴らす20打でも50打でも、最後の1打がいちばん高く、いちばん強い。叩く速さに左右されない。
ボタンの光、指の位置の輪連打の速さ。0.45秒以内に次を叩くと明るくなり、止まると落ちる試作の「気持ちいい」を残す。前回の言葉では「止まって落ちるのは、連打の勢いだけ」。
ドパの粒いつも同じ1打で1粒、ボタンから「+N ドパ」へ飛ぶ。1打が1ドパであることを、数より先に目で見せる。

最後の1打では、上の3つにフィナーレが重なります。粒が弾け、「やったった！」の文字が出て、和音と長めの振動が鳴る。ここに強まり2と3が乗ります。

強まり 2

強まり 3

節目の札

届いた節目ごとに札が1枚、フィナーレの下に積まれる。札1枚につき金色の粒と音を1つ足す。DT と DPW の節目は連打の途中でまたぐこともあり、そのときはまたいだ1打で札を出す。途中で閉じた記録でも同じ。

04-2 / dopadopa

連打の途中を、パチンコのように

実装を見る前に、開発者から注文が入りました。「連打中にもっとドーパミンが出るように、パチンコの演出のようにドパドパと」。04 の設計で山が来るのは、最後の1打だけでした。2打目から19打目までは、音程が少しずつ上がり、輪と粒が出るだけです。20打のうち19打が、ほぼ同じ見た目で過ぎていきます。

パチンコの演出は、当たりを告げる前に段階を踏みます。リーチがかかり、背景が変わり、「激熱」が出て、最後にボタンを押させる。ドパ〇〇の調査では、ドパ電卓がこの文法を借りていました（確定演出／煽り演出）。連打の途中に、この段階を置きます。呼び名は開発者の言葉から取って、ドパドパとします。

ただし、パチンコと決定的に違うところが1つあります。結果がもう決まっていることです。20回しゃがんだ人は、20打叩けば必ず20ドパ入り、必ずフィナーレが出る。外れはありません。だから段階も、くじで決めずに、何打目まで来たかで決めます。同じ20打なら、毎回同じところで激熱が来る。ドパ電卓が、入力した数で演出のランクを決めていたのと同じ作りです（確定報酬のまま）。

表1-2　ドパドパの段階（目標回数 20 の場合）

段階入る1打入った瞬間その段階のあいだ、1打ごと
NORMAL1打目なしいまの輪と粒。指の位置から小さな「ドパ」の文字が飛ぶ
CHANCE進み具合 30%（20打なら6打目）「CHANCE」の帯がボタンの上を横切る。上がる音を1つボタンの縁が dopa 色で脈打つ。「ドパ」の文字が大きくなる
激熱進み具合 60%（12打目）「激熱」の判子がドンと押され、画面が1度揺れる。低い音と重い振動背景に dopa の集中線がゆっくり回る。ボタンが赤みを帯びた金になる。叩く音に低音を重ねる

目標回数が 10 より少ないときは、PUSH を残り1打にする。5打で CHANCE、激熱、PUSH が詰まりすぎないように、段階の入り口が同じ1打に重なったら、強いほうだけを出す。

段階とは別に、速く叩き続けたときの返しを足します。0.45秒以内に叩き続けると、指の上に「ドパドパ ×12」のように続いた打数が出て、飛ぶ文字が「ドパ」から「ドパドパ」に変わる。数字は勢いを見せるだけで、ドパは増えません。前回、XP が2倍になる時間を借りなかったのと同じ理由です。1ドパが1回のスクワットでなくなる。

もう1つ、パチンコから借りるものがあります。虹です。この連打の最後の1打で節目に届くと分かっているとき（連続30日目になる、DT が1,000を超える）、PUSH に入った瞬間にボタンの縁が虹色に回り出します。パチンコでいう先バレで、当たりが来ることを前もって告げる演出です。ここでも、くじは引いていません。記録から計算すれば、最後の1打で何が起きるかは叩く前から分かっています。

盛っても守るもの。画面全体の明滅は1秒に3回まで（ひかえめモードの考え方）。「視差効果を減らす」が入っているときは、揺れ、集中線、飛ぶ文字を止め、段階の文字（CHANCE、激熱、PUSH）とボタンの色だけを変える。音と振動は変えない。どの見た目も、修正イメージ ドパドパの見本 で叩いて確かめられる。

04-3 / fullscreen

ボタンの外へ、画面ぜんぶへ

ドパドパを入れても、開発者の答えは「まだドーパミンが全然足りません」でした。添えられたのは、パチンコの演出画像が3枚。7が3つ並び、虹色の光が画面の端まで噴き出している。金属の文字で「NEXT 確定」。金の炎の中に「限界突破」。どれも、画面の隅々までが演出です。

見比べて、足りないものが分かりました。04-2 のドパドパは、ボタンのまわりで起きていました。集中線もボタンの後ろだけ、判子もボタンの角だけ。画面の上の帯と下のカードは、激熱のあいだも、明るい地のまま静かに座っている。パチンコの台に、そんな静かな場所はありません。

そこで、演出の舞台を画面全体に広げ、3つの大きな演出を足します。どれも、くじは引きません（決定 17）。

04-4 / fever

フィーバータイムと、5倍の派手さ

声と効果音がそろった実機で、開発者の答えは「演出がまたフラットな感じ」でした。注文は5つ。背景をもっと盛る。文字の演出を5倍派手に。BGM をゴリゴリ鳴らす。777 のリールはやめて、100ドパごとに「100 ドパ突破」。そしてリールの代わりに、10秒間の連打でドパを大量に取れるフィーバータイム。

いちばん大きいのは最後の1つで、これまでの決めごとを2つ動かします。1つはスクワット1回で1ドパという数え方（題材の決定 07、本作りの決定 18）。もう1つは、くじを引かないという線（決定 17）です。開発者の答えは、どちらもはっきりしていました。フィーバーのドパは DT と DPW に入れる。始まるかどうかは、1打ごとのくじで決める。

04-5 / squad

05 / dpw

DPW を、曜日で区切るか

前回は、DPW を月曜の午前4時に0へ戻すと決めていました。Duolingo の週のリーグと同じ区切りです。レビューで、開発者がこれを改めました。DPW は直近7日間のドパの合計にします（開発者が決定）。

曜日で区切ると、月曜の朝の DPW は、叩いた1回分しかありません。何曜日に開くかで、数字の重みが変わってしまう。直近7日間なら、いつ開いても「この1週間でどれだけしゃがんだか」が同じ物差しで出ます。リーグのような、みんなで同時に締める相手がいないので、曜日にそろえる理由もありません。

表2-2　直近7日間にしたときの数え方

数決め方補足
DPW今日と、その前の6日の記録日の回数を足す日の区切りは午前4時のまま。
前の7日7日前から13日前までの合計「先週」の代わり。カードには「前の7日 300」と出す。
自己ベスト昨日までのどの日で区切った7日間の合計のうち、いちばん大きいもの今日を含めると、叩くたびに自分を超え続けてしまう。
自己ベストの節目今日の DPW が自己ベストを超えた1打。1日に1回まで記録を始めて8日目から。それより前は、7日まるごとの区間が1つもなく、超える相手がいない。

代わりに、DPW は叩かなくても減るようになりました。午前4時を過ぎるたびに、7日前の1日分が抜けるからです。7日前に60ドパためた人は、今朝開くと、何もしていないのに DPW が60減っています。月曜にまとめて0になるより穏やかですが、「減った」と見える日は前より増えます。画面では減ったことを強調せず、数字をそのまま出します。

06 / streak

休み券は、保存しなくても数えられる

前回は、休み券を記録と別に保存するつもりでいました。使った日は、記録のない日だからです。ない記録から、使ったことは読めない。そう考えていました。

ところが、休み券の配り方と使い方には、人の判断が1つも入りません。7日続くたびに1枚、持てるのは2枚まで、叩かなかった日に自動で使う。最初の記録の日から今日まで1日ずつたどれば、どの日にもらい、どの日に使ったかは毎回同じ答えになります。保存するのは記録だけで足ります（開発者が了承）。

図1　記録を1日ずつたどる

  1. 1記録のある日：連続日数を1増やす。7の倍数になったら休み券を1枚足す（2枚を超えない）。
  2. 2記録のない日（今日より前）：休み券があれば1枚使い、連続日数はそのまま。なければ途切れる。連続日数は0に、休み券も0枚に戻す。
  3. 3今日：記録がなければ、まだ何もしない。今日が終わるまでは途切れていない。

休み券で埋めた日は、連続日数に数えません。つなぐだけです。数えてしまうと、14日目に2枚もらった人は、何もしなくても16日まで伸びます。途切れたときに休み券を0枚に戻すのは、同じ持ち札で次の連続を始めさせないためです。持ち越せると、途切れる直前まで休み券をためる意味が変わってしまいます。

「どの日か」は、記録を作った瞬間に決めて記録に書き込みます。記録日と呼びます。午前4時より前なら前の日です。日時だけを保存して毎回計算し直す手もありますが、それだと海外へ行った人の過去の記録が、時差の分だけ別の日に移ります。ロサンゼルスで夜22時に叩いた記録は、帰国して東京で開くと翌日の14時になり、記録日が1日後ろへ動く。叩いたその場の日付を写しておけば、どこで開いても日はずれません。

表3　途切れたときと、休み券を使ったときに出すもの

場面出すもの出さないもの
途切れたあと、最初に開いたときカードを1枚。「連続記録は29日で止まりました」の下に、最長記録と DT を大きく。「ためた 987 ドパは、そのまま」。ボタンは「今日の1回から」「0日」の表示。上の日数は「今日の1回で1日目」と出す
休み券が使われたあと、最初に開いたとき上に2秒だけ帯を出す。「休み券を1枚使って、29日連続をつなぎました」「昨日は休みましたね」のような責める文

どちらも1回出したら終わりです。どこまで見せたかは、端末の設定として小さく覚えておきます。記録とは別の、消えても困らない値です。

07 / reminder

通知を、責めずに出せるか

前回の調査で、通知には2つの顔が見えました。Duolingo の深夜の「連続記録が切れそう」は効果が大きかった。一方で、罪悪感をあおる作りは批判の的になっている。そして最も人を戻したのは「この通知は効いていないようなので、しばらく止めます」でした。

出します。ただし、3つの縛りを付けます。

  • 頼まれてから：初めて叩き切ったフィナーレのあとに、「夜、今日まだのときだけ知らせますか？」と1度だけ聞く。起動直後には聞かない。何をするアプリかも分からないうちに許可を求めても、断られるだけだからです。
  • まだの日だけ、1日1回：既定は 21:00。その日に記録が1件でもあれば、その日の分は取り消す。
  • 7日で黙る：開かれるたびに、先の7日分を予約し直す。7日目の通知だけ文面が違い、「しばらく通知を止めます。また開いたら再開します」。7日開かなければ、それきり何も届かない。

3つ目は、通知の仕組みから自然に出てきた形でもあります。端末の中だけで出す通知は、届く時刻に「今日もう叩いたか」を確かめられません。先に予約しておき、叩いたら取り消すしかない。予約を7日分に限れば、止める処理を別に書かなくても、開かれない限り7日で尽きます。文面は4つを日ごとに回します（中身は今日まだ通知）。

08 / sound

マナーモードのときは黙る

試作では、マナーモードでも音を鳴らしていました。「音が出ない」で迷わないためです。本作りでは、マナーモードに従って黙ります（silent-mode-sound を閉じる）。

決め手は、いつでも記録できることでした。職場で昼食のあとに叩けば、20個の「ポン」が事務所に響きます。手触りの試作でも、振動と光だけでどれだけ残るかは確かめていません。ただ、試作の Q2 で音を150ms遅らせても指が気づかなかったのは、振動と光が「叩いた感じ」の大半を背負っているからかもしれない。黙っても振動は残ります。ほかのアプリの音楽も止めません。

  1. 01画面は1枚（ホーム）。設定は下から出すシート。記録の一覧画面は作らない。
  2. 02記録は、残りが0になったとき、60秒叩かなかったとき、アプリを離れたときに1件として閉じる。叩き切ったあと1.2秒は叩いても数えない。
  3. 03途中で閉じた記録も、連続記録の継続に数える。
  4. 04記録の保存は閉じたときに1回だけ。叩いている間は書き込まない。
  5. 05音の高さと振動の強さは進み具合（8段階）、光は連打の速さで決める。1打で1粒のドパを飛ばす。
  6. 06節目は DT 100／1,000／10,000／100,000、連続 7／30／100／365 日とその先365日ごと、DPW の自己ベスト更新（1日に1回まで、記録を始めて8日目から）。
  7. 07休み券は保存せず、記録から計算する（開発者が了承。前回の決定 11 を改める）。休み券で埋めた日は連続日数に数えない。途切れたら休み券も0枚に戻る。
  8. 08記録を取り消す仕組みは作らない（開発者が決定）。課題 undo-record に残す。
  9. 09記録日は、記録を作った瞬間の端末の時刻から決めて記録に書き込む。
  10. 10途切れたら、最長記録と DT を前に出すカードを1度だけ出す。「0日」とは表示しない。
  11. 11通知は、初めて叩き切ったあとに1度だけ聞く。まだの日だけ1日1回、既定 21:00。予約は7日先までで、7日目は「しばらく止めます」。
  12. 12マナーモードでは音を鳴らさない（.ambient）。ほかのアプリの音は止めない。
  13. 13保存は SwiftData。記録以外の小さな値は UserDefaults。
