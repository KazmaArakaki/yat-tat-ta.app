App Store の審査に出す準備

開発者の注文

App Store の審査に出す準備（説明文、スクリーンショット、年齢制限の質問など）に進む

TestFlight に 1.0 (1) を出し、本番の Firebase に記録が入るのを確かめたところ（前回のセッション）。

01 / what's left

審査に出すまでに空いている欄

半分はもう埋まっています。プライバシーポリシーとサポートの URL、App のプライバシーの表示、輸出コンプライアンス（Info.plist）、ビルド。どれもこの2日のセッションで済ませました。

空いているのは、ストアの店先に並ぶもの（説明文、キーワード、スクリーンショット）と、審査の人に向けた答え（年齢制限の質問、審査メモ）です。前者は文を書けば終わる、と思っていました。ところが、書き始めると年齢制限の質問とぶつかります。

英語の説明文には、2026-10-06 に決めた「pachinko-style effects」という句がありました。年齢制限の質問の「疑似ギャンブル」は、Apple の定義では「お金を使わない賭け」です。何も賭けない Yat Tat Ta は「なし」と答えられる。それでも、説明文にパチンコとあれば、審査の人が疑似ギャンブルを疑う余地が残ります。疑われれば 13+ です。

もう埋まっている

プライバシーポリシーとサポートの URL、App のプライバシー、輸出コンプライアンス、ビルド 1.0 (1)、アカウントの削除（審査の条件）

このセッションで埋める

サブタイトル、プロモーション用テキスト、説明文、キーワード、カテゴリ、年齢制限、審査メモ、配信地域、スクリーンショット

02 / decisions

決めたこと

  • 決定　年齢制限は 9+。「健康やウェルネスの話題」だけを「あり」と答える。Apple の定義の例に「運動のすすめ」が入っているから（開発者が決定、2026-10-07）。
  • 決定　掲載情報にパチンコの語を書かない。英語の説明文の「pachinko-style」は「arcade-style」に改める。疑似ギャンブルは「なし」と答える（開発者が決定、2026-10-07）。
  • 決定　スクリーンショットは、上に見出しの帯を付けた6枚（開発者が決定、2026-10-07）。
  • 提案　カテゴリはヘルスケア／フィットネス、セカンダリはエンターテインメント。食後に体を動かすアプリとして探されたいが、中身の半分は演出なので。
  • 提案　デモ用のアカウントは作らない。ログインは Apple だけなので、審査の人は自分の Apple ID で入れる。「サインインが必要」はチェックを外し、審査メモで説明する。
  • 提案　配信は中国本土を除くすべての国と地域。中国本土は ICP の登録番号が要る。
  • 提案　スクリーンショットは 6.9 インチと 6.3 インチの両方を撮る。Apple の仕様のページは、中くらいの画面を必須と書きながら、空なら大きい画面のものを縮めるとも書いていて、どちらが効くか読み切れなかった。スクリプトで撮るので、2台にしても手間はほとんど増えない。

文言の全文と、年齢制限の質問ごとの答えはApp Store の掲載情報に置きました。App Store Connect に入れるときは、そちらからコピーします。

03 / risks

審査で止まりそうなところ

いちばん心配なのは、最初の起動でログインを求めることです。審査ガイドライン 5.1.1 には「アカウントに基づく大きな機能がないなら、ログインなしで使わせること」とあります。スクワットの回数を数えるだけのアプリに見えれば、ここで止められるかもしれない。

Yat Tat Ta の場合、記録はアカウントに置いてあり、機種を替えても戻ることがログインの理由です（アカウント、開発者が決定、2026-10-07）。この理由を、審査メモの2段落めにそのまま書きました。それでも止められたら、そのとき「ログインせずに始め、あとでアカウントに移す」作りを考えます。いまから作り替えるほどの見込みはない、と判断しました。

もう1つは演出です。CHANCE、激熱、FEVER と画面が騒ぐので、説明文から語を外しても、審査の人がアプリを触って疑似ギャンブルを思い浮かべることはありえます。審査メモの4段落めで「賭けも、通貨も、購入も、景品も、広告もない」と先に書いておきます。

04 / screenshots

シミュレーターで叩いたあとの画面を撮るには

シミュレーターでは連打できません。そのために、演出の場面を叩かずに出す見本（起動引数 -demo）がすでにあります。フィーバーも筋肉確定も、これで出せる。

足りないのは記録です。見本はメモリだけの空の記録で開くので、帯は「1日目」、カードはドパ0、履歴は空のまま。ストアに並べるには寂しすぎます。そこで、見本の記録（起動引数 -seed）を足します。昨日まで34日ぶん、朝昼晩の時刻に少しずつばらつきを持たせ、途中に休み券で埋まる日を1日入れる。今日は1件もなく、スプラッシュでは空いた今日の席が見えます。

見出しの帯は、撮ったあとの画像に Swift のスクリプトで描き足します。macOS に入っている CoreGraphics だけで描けるので、Python の画像の部品のような道具を増やさずに済む。文字はアプリと同じ、システムの丸ゴシックの太字です。

見本

見出しの帯の見本（6枚、日本語と英語）

帯の高さ、文字の大きさ、画面の縮め方を、できあがりの比率で並べた。

05 / implementation

作るもの

保存しているデータには触れません。アプリに足すものは、どれも Debug のビルドにだけ入ります。審査に出す 1.0 (1) は出し直さなくてよい。

  1. 1. 見本の記録 ShotSeed を足し、起動引数 -seed があれば、演出の見本をこの記録で開く
    帯、カード、履歴、スプラッシュに、続けている人の数を出すため。乱数の種を決めておき、何度撮っても同じ記録になるようにする。撮り直したときに数字が変わると、日本語と英語で画面が食い違う。
  2. 2. 演出の見本に home（何も出さない）と history（履歴のシートを開く）を足す
    4枚めと5枚めの画面。いまの見本は演出の場面しか出せず、ふだんのホームと履歴のシートを開く手段がない。
  3. 3. ios/Design/screenshots.sh：Debug でビルドし、2台のシミュレーターで状態表示をそろえ、日本語と英語で6枚ずつ撮る
    言語は起動引数（-AppleLanguages）で切り替える。手で撮ると、時刻や電池の表示、待つ秒数が1枚ずつ違ってしまう。
  4. 4. ios/Design/compose_screenshots.swift：撮った画像の上に見出しの帯を描き、できあがりを番号の順に書き出す
    見出しの文言は、このスクリプトの中の表に置く。アプリの String Catalog には入れない。アプリの画面には出ない言葉だから。
  5. 5. ios/Design/Screenshots/ を .gitignore に足す
    24枚で数十 MB になる。スクリプトでいつでも撮り直せるので、Git に置く理由がない。
  6. 6. テスト：ShotSeed の記録で、連続記録が続いていて、今日の記録が0件であること
    日付から記録を作るので、撮る日によって連続記録が途切れて見える作りにしてしまうと気付きにくい。帯が「途切れた」表示のまま撮られるのを防ぐ。

06 / developer

開発者にお願いすること（約45分）

App Store Connect の画面での作業です。文言はApp Store の掲載情報のコピーのボタンから取れます。

  1. 1　約10分

    撮ったスクリーンショットを目で見て、日本語と英語の 6.3 インチの枠（必須）に上げる。6.9 インチは任意で、メディアマネージャーから足す。

  2. 2　約15分

    日本語と英語の、サブタイトル、プロモーション用テキスト、説明文、キーワードを入れる。カテゴリと著作権を入れる。

  3. 3　約5分

    年齢制限の質問に答え、9+ になることを確かめる。

  4. 4　約5分

    価格（US$0.99）と配信地域（中国本土を除く）、コンテンツの権利を入れる。有料 App の契約、税金のフォーム、銀行口座を「ビジネス」で済ませる。

  5. 5　約10分

    ビルド 1.0 (1) を選び、審査メモと連絡先を入れ、「サインインが必要」を外し、公開を「手動」にして審査に出す。

07 / build

作ったところ

  • ShotSeed を足した。連続33日（34日のうち1日は休み券）、DPW 468、DT 1,936 の人になる。テストを3つ足し、全91個が通る。
  • 最初に撮ったホームでは、休み券を使ったという帯が画面の上にかぶった。帯は「まだ見せていない休み券」があると出るので、見本の設定で見せたことにした。
  • 自己ベストは昨日で終わる7日も数えるので、今日まだ叩いていない見本では、DPW が自己ベストを超えることはない。直近7日を濃くして、前の7日（361）より多く見せるところまでにした。
  • フィーバーの見本は、そのままだと「+0 ドパ」と出る。-seed のときだけ、24ドパ取ったところから始める。
  • 待ち時間は撮りながら決めた。squad は約6秒たってから PUSH になる（見本の記録だと、97打の途中で DT が2,000をまたぎ、先にドパ突破が出る）。起動したてのシミュレーターでは最初の数枚が白いまま写ったので、撮る前に1回開いておくようにした。
  • 見出しの日本語は、システムに任せると細い字で描かれた。代わりの書体にヒラギノ角ゴの W8 を指定した。
  • App Store Connect で必須の枠は 6.3 インチ（Dynamic Island 搭載 iPhone、中型ディスプレイ）だけで、6.9 インチは任意だった。開発者が日本語の6枚を 6.3 インチの枠に上げた（2026-10-07）。
  • 著作権と運営者の表記を「Kazma Arakaki」から「Kazuma Arakaki」に改めた（開発者が決定、2026-10-07）。プライバシーポリシーの運営者名と、公開4ページの © の行も同じに直した。ポリシーには改定日を足していない。制定日と同じ日で、まだ利用者がいない時点の表記の直しだから。
  • 価格を無料から US$0.99 に改めた（開発者が決定、2026-10-07）。有料で売るには、有料 App の契約が有効になっている必要がある。
  • アプリ情報で「規制対象の医療機器か」を聞かれ、「いいえ」と答えた。理由は掲載情報の表3。
  • 24枚を撮り、6枚とも狙った場面になっていることを目で確かめた（2026-10-07）。6.9 インチは 1320 × 2868、6.3 インチは 1206 × 2622。残りは App Store Connect への入力（上の6）。
  • 開発者が App Store Connect に文言、スクリーンショット（日本語と英語の 6.3 インチ）、年齢制限（9+）、価格（US$0.99）、配信地域、審査メモを入れ、ビルド 1.0 (1) を審査へ提出した（2026-10-07）。公開は手動。審査で止められたら、理由を見て新しいセッションで直す。
