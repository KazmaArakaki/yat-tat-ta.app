開発者の注文

privacy-policyから進めてください

課題 privacy-policy（優先度：高）。記録を Firestore に置き、アカウントを作るようになったので、リリース前に必要になった。

01 / where

どこに出すか

App Store は、どのアプリにもプライバシーポリシーの URL を求めます。誰でも開ける場所が要るのに、このプロジェクトには公開しているサイトがありません。Git のリモートもなく、このドキュメントもどこにも出していない。

そこで、記録を置いている Firebase のプロジェクトで、Hosting を使って出します（開発者が決定、2026-10-07）。ルールを反映したのと同じ firebase-tools で出せるので、増える道具がありません。URL は https://yat-tat-ta.web.app/privacy/ です。

App Store Connect では、ポリシーの URL を言語ごとに入れられます。日本語と英語でページを分け、英語は /privacy/en/ に置きます。サポートの URL も申請に要るので、トップページを問い合わせ先とポリシーへの入り口にして兼ねます。

    プライバシーポリシー

    firebase/public/privacy/index.html

  • /privacy/en/

    Privacy Policy

    firebase/public/privacy/en/index.html

  • /

    サポート

    firebase/public/index.html

  • /en/

02 / decisions

決めたこと

  • 決定　公開は Firebase Hosting（開発者が決定、2026-10-07）。
  • 決定　運営者は、App Store の販売元と同じ個人名（開発者が決定、2026-10-07）。表記は「Kazma Arakaki」（開発者が確認、2026-10-07）。同じ日の App Store の審査の準備で「Kazuma Arakaki」に改めた（開発者が決定、2026-10-07）。
  • 決定　問い合わせ先は support@yat-tat-ta.com（開発者が決定、2026-10-07）。
  • 決定　出す前の見た目は、開発用のコンテナの reverse-proxy で http://site.yat-tat-ta.localhost/ から確かめる（開発者の注文、2026-10-07）。
  • 提案　冒頭に「集めるのはログインの番号と記録だけ」「広告や分析に使わない」「いつでも全部消せる」の3行を置く。本文を読まない人にも、預けるものの大きさが伝わる。
  • 提案　公開ページは外のフォントを読み込まない。ポリシーを開いただけで、開いた人の情報がフォントの配信元へ送られるのを避ける。
  • 提案　健康のことは書かない。記録は回数と日時で、健康のために集めるとは書かない（健康効果の書き方）。

03 / contents

ポリシーに書いたこと

書いたのは、アプリが実際にしていることだけです。集めるのは、ログインの番号と記録の5つの列。目標回数や通知の設定は端末の中だけにあり、外へ送らないことも書きました。

迷ったのは、預ける先の書き方です。記録は東京に置いていますが、ログインの番号を扱う Firebase Authentication は場所を選べません。日本の外で処理されうるので、米国の Google LLC に預けていることと、米国の制度を確かめられる個人情報保護委員会のページを書きました。外国にある事業者へ預けるときに、日本の法律が求める説明に沿わせたつもりです。とはいえ、法律の専門家に確かめたわけではありません。リリースの前に、気になるところがあれば専門家に見てもらうのが安全です。

下書き

Privacy Policy（英語）
  1. 1　集める情報（番号、記録、通信に伴う情報）と、端末の中だけに置く情報
  2. 2　使う目的。広告、分析、トラッキングには使わない
  3. 3　預ける先（Google の Firebase、保存場所）と Apple でのログイン
  4. 4　保存する期間と、アプリからの消し方
  5. 5　安全管理（暗号化、自分の記録だけ読み書きできるルール）
  6. 6〜8　開示や削除の請求、変更のしかた、問い合わせ先

04 / app store

App Store のプライバシーの表示

App Store Connect の「App のプライバシー」に答える内容です。区分は申請のときに Apple の説明で確かめます。Firebase の SDK が自分で集めるものがないかも、Firebase の App Store 向けの説明で確かめてから答えます。

表1　答える内容
種類答え中身
ユーザ ID集める。利用者に結びつく。目的は「アプリの機能」Firebase Authentication の利用者 ID
フィットネス集める。利用者に結びつく。目的は「アプリの機能」スクワットの回数。Apple の区分では運動のデータにあたる見込み
トラッキングしない広告にも、ほかの会社のデータとの突き合わせにも使わない
そのほかの種類集めない名前、メール、位置、連絡先、使い方の分析、診断データ

06 / implementation

作るもの

保存しているデータには触れません。

  1. 1. firebase/public/ に公開ページを置く（日本語と英語のポリシー、サポートページ、共通のスタイル）。firebase.json に Hosting を足す
    ポリシーの文面そのもの。ルールと同じ firebase-tools で出せて、Git のリモートが要らない。
  2. 2. ログイン画面の「名前とメールアドレスは受け取りません。」の下に「プライバシーポリシー」のリンク
    ログインする前に、何を預けるかを読めるようにする。見本（ページ：ログイン画面）にはもう置いてある。
  3. 3. 設定シートのアカウントの欄の下に「プライバシーポリシー」の行
    ログインしたあとにも読み返せる場所が要る。
  4. 4. URL を1か所（Legal）にまとめ、端末の言語が日本語なら /privacy/、それ以外は /privacy/en/ を開く
    開発の言語を英語にしているので、日本語でも英語でもない端末には英語を出す、という多言語の決まりとそろえる。
  5. 5. 文言を日本語と英語で足す
    多言語の決まり事で、文言を足すときは2言語同時。
  6. 6. 開発者が公開する（npx firebase-tools deploy --only hosting）。App Store Connect にポリシーとサポートの URL を入れ、プライバシーの表示を埋める
    公開と App Store Connect の操作は、開発者のアカウントでしかできない。

07 / build

作ったところ

  • 開発用のコンテナの reverse-proxy に site.yat-tat-ta.localhost を足し、開発者が公開ページの見た目と運営者名を確かめた（2026-10-07）。
  • URL を Legal にまとめた。言語は、アプリが文言に使っている言語（Bundle.main.preferredLocalizations）で選ぶ。アプリが英語で出ているのに、ポリシーだけ日本語で開くことがない。
  • ログイン画面の一番下と、設定シートのアカウントの欄の下に「プライバシーポリシー」を置いた。文言を1つ足した（Privacy Policy）。テストを2つ足し、全87個が通る。
  • 開発者が Firebase Hosting に公開し（2026-10-07）、iPhone の Safari での表示と、設定シートから開けることを確かめた。URL は https://yat-tat-ta.web.app/privacy/ と /privacy/en/、サポートは / と /en/。残りは App Store Connect への入力で、課題に残した。
  • Xcode を開いたままコマンドラインでビルドするときは、別のビルド置き場（-derivedDataPath）を使い、ダウンロード済みの部品を読むだけにする（-clonedSourcePackagesDirPath、-disableAutomaticPackageResolution）。前のセッションの、ダウンロードのぶつかりを避けるため。
