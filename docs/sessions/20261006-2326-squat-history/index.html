スクワットの履歴を見る

開発者の注文

いつ、どれだけ叩いたかを1枚で

記録は全部残っているのに、見られるのは今日の分だけ。
開発者が手描きのラフを1枚くれた。縦に時刻、横に日付、叩いたところに人形。
人形は量が多いほど大きく、背景には日ごとのドパと7日移動平均の網掛け。押せば詳細が出る（網掛けは、レビューで薄い面に改めた）。

01 / rough

ラフの読み方

ラフで迷ったのは縦軸の向きでした。グラフの縦は量に使うものだと思い込んでいた。 ところが目盛りは 9:00 と 12:00 で、12:00 のほうが上にあります。縦は時刻で、量は人形の大きさと背景の面が受け持つ。 読み方を、書き込みごとに並べます。

ラフの書き込み読み方こちらで補ったこと
縦の目盛り 9:00、12:00縦はその日の時刻。12:00 が 9:00 より上にあるので、上ほど遅い範囲は午前4時から翌朝4時。記録日の区切りに合わせ、夜食のあとの1件もその日の列に入れる
横の 9/9、9/10横は日付1日1列、1画面に7日ほど。横になぞって過去へ戻る。開いた直後は今日が右端
「スクワットをした日時をアイコンで表示」「量が大きければアイコンも大きくなる」記録1件をアイコン1つで、その日のその時刻に置くアイコンはスクワット隊のしゃがんだ人形。面積をドパに比例させる。フィーバーのドパがある記録は dopa 色
網掛けの「DOPA 日毎獲得量」と「DOPA 7日移動平均」2枚の面グラフを背景に重ねる同じ目盛りに載せ、数字は出さない。斜線は使わず、色の違う縁の線と薄い塗りで見分ける（開発者のレビュー）。7日移動平均は DPW を7で割った数
「タップで詳細表示」アイコンを押すと、その記録の詳細が出る時刻、回数、フィーバーのドパ。その日の件数と合計、7日移動平均も添える

02 / place

どこから開くか

最初は、今日の記録のシートを広げるつもりでした。記録を見せる場所はもうあり、そこに過去の日を足せば済む、と。 ただ、ラフの中身は今日の記録の続きというより、DPWとDTの内訳です。日ごとのドパを積めば DT、7日分を足せば DPW になる。 開発者は DPW と DT のカードを入口に選びました。今日の記録のシートは、今日の1件を消す場所のまま残ります。

カードを押せるようにするだけなので、ホームの部品は増えません。今日の記録の帯と同じく、右上に「›」を付けて押せることを示します。

03 / mock

修正イメージ

左：ホームのカード（「›」が付くだけ）。右：履歴のシート。グラフは横になぞれて、人形を押すと下の行が変わります。全画面の動く見本は ui／履歴、状態ごとの見た目は ui／履歴のグラフ。

04 / spec

端の場面

見え方の決まりは機能ページにまとめました。ここには、ラフに描かれていない場面だけを置きます。

場面決めなぜ
記録がない7日分の空の列と「叩くと、ここに人形が並びます。」空のグラフだけでは、壊れて見える
始めて7日目まで列は少なくとも7日分。最初の記録日より前の列は空1画面に7日という見え方を、初日から崩さない
人形が重なる新しい記録を上に描く。押せる範囲は30pt 四方以上同じ時間帯に2件叩くことは少ない。重なっても押し分けられればよい
叩いている最中DPW と DT のカードは押せない開いている連打はまだ記録ではない。今日の記録と同じ決まり
開いたまま午前4時をまたぐ開き直すまで描き直さない見ている途中で列がずれると、押そうとした人形が逃げる
ひかえめモード開いたときの人形の弾みを出さないひかえめモードの決まり
VoiceOver日の列を1つの要素にし、「10月3日 土曜、2件、42ドパ、7日平均32」と読む。人形はその中の要素で「19時40分、10回、フィーバー12ドパ」グラフの形は聞いても分からない。数で読めれば足りる

保存するデータは変わりません。記録の叩き始めた時刻（startedAt）と記録日（day）、回数、フィーバーのドパから、すべて描けます。

05 / detail

作る場所

所要はあわせて3〜4時間。グラフの描き方（重さ）がいちばん読めないところです。

場所変更なぜ
Model/History.swift（新規）記録の一覧と今日から、日の列を作る。列ごとにドパの合計、7日移動平均、人形（4時からの分、回数、フィーバーのドパ、記録の id）。最初の列は「最初の記録日」と「今日の6日前」の早いほう計算を画面から切り離し、テストで確かめる。Ledger と同じく保存しない
AppModelhistory() を足す。全記録を読み、休み券の日（ledger.streak.restPassDays）と合わせて History を返すシートを開くときに1回だけ読む。叩くたびには作らない
History/HistoryView.swift（新規）シート本体。見出し、凡例、グラフ、詳細の行。.presentationDetents([.large])今日の記録、設定と同じく、ホームに重ねて閉じれば戻る
History/HistoryChart.swift（新規）横の ScrollView に日の列を LazyHStack で並べ、人形を置く。面グラフは ScrollView の後ろに置いた Canvas 1枚に、見えている範囲だけ描く（onScrollGeometryChange でずれを受ける）。.defaultScrollAnchor(.trailing) で今日を右端に1年分を1枚の絵にすると幅が1万2千pt を超え、メモリを食う。見えている7日分だけなら軽い
SquatFigure（新規の Shape）しゃがんだ人形を描く。点は SquatterLayer の「しゃがむ」と同じものを1か所に置いて共有する隊と同じ姿にする。片方だけ直して形がずれることを防ぐ
TotalsCards、HomeView2枚のカードを Button にし、右上に「›」。叩いている最中は押せない。シートを出す入口をカードに置く（開発者が決定）
Localizable.xcstrings「履歴」「日ごとのドパ」「7日移動平均」「人形を押すと、その記録が出ます。」「叩くと、ここに人形が並びます。」と、VoiceOver の読み上げ。英語も同時に多言語の決まり事。訳語表に History と 7-day average を足す
テスト7日移動平均、始める前の日を0として数えること、午前1時の記録が前の日の列の上端に入ること、記録がないとき7列、最初の列の決め方グラフの形はシミュレーターで見るしかないが、数は機械で確かめられる
docs実装でずれたところを、機能、画面、コンポーネントの見本に戻す見本と実物を揃えておく

06 / review

見てほしいところ

ラフにない数と形を、こちらで決めました。開発者がレビューし、5つともこのままでよいとした（2026-10-06）。同じレビューで、背景の面の斜線をやめた。

  1. 人形はしゃがんだ姿にそろえた。ラフの 9/10 は立ち姿に見えました。姿で何かを分けているのか読み取れなかったので、1つにしています。
  2. 1画面に7日、開いた直後は今日が右端。DPW の7日と同じ幅です。30日を一度に見たいなら、列を細くする案もあります。
  3. 人形の大きさは面積をドパに比例（14〜46pt）。20ドパで約29pt、52ドパで約47pt（上限で46pt）。差が小さく見えるなら、高さを比例させる手もあります。
  4. 休み券の日に青い札を足した。ラフにはありません。人形のない列が、途切れた日に見えないようにするためです。
  5. 面グラフに目盛りの数字を出さない。数は詳細の行で読みます。目盛りを足すと、時刻の目盛りと2つになって混ざります。

07 / decisions

決めたこと

  1. 01履歴を作る。縦に時刻、横に日付。記録1件を人形1つで置き、ドパが多いほど大きく。背景に日ごとのドパと7日移動平均。押すと詳細（開発者のラフ）。
  2. 02入口は DPW と DT のカード。今日の記録のシートはそのまま残す（開発者が決定）。
  3. 03見るだけ。消すのは今日の記録から。
  4. 04保存の形（SquatRecord）は変えない。
  5. 05背景の面に斜線は使わない。縁の線と薄い塗りで描く（開発者のレビュー）。
