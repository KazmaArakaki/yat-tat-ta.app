X の広報担当AI

開発者の注文

審査待ちの間に、X のアカウントへ投稿する AI について考えたい

アカウント @yattattadotcom は作ってあり、自己紹介に「作った本人（とAI）が運用しています」と書いた（前のセッション）。名前は「広報兼サポート担当」。

01 / rules

X は AI の投稿を許しているのか

2026年の X は、AI のアカウントを締め出しにかかっています。170万の AI ボットを消し、X の幹部は「人が画面を叩いていないアカウントは止める」とまで言った、と報じられました。広報担当を AI にした途端、アカウントごと止められるのではないか。最初に引っかかったのはそこでした。

読み進めると、線は別のところに引かれていました。幹部自身が「公式の API なら使ってよい」と添えています。止められているのは、画面を自動で操作するボットと、頼まれてもいないのに他人の投稿へ返信して回る AI です。自分の投稿を API で出すこと、AI が書いた文を出すことは、X の自動化のルールで認められています。

表1　自動で動かすときの X のルール（2026年4月改定。公式のページは 403 で読めず、検索の抜粋と解説で確かめた）
してよいしてはいけない
公式の API で、自分の投稿を出す。AI が書いた文でもよいブラウザやアプリの画面を自動で操作して投稿する
自分あての返信や引用に、1回だけ自動で返信する頼まれていない人へ、自動で返信やメンションを送って回る
予約投稿同じ文の投稿を繰り返す。誤解を招くリンクを自動で送る

API で動かすアカウントは、プロフィールに「自動化」のラベル（Automated）を付ける決まりがある。ラベルは、運用している人のアカウントとつながる。また、API からの返信は、相手がこちらをメンションしたか引用したときにしか送れなくなった（2026年2月）。

02 / role

広報担当AI の仕事

広報担当AIは、@yattattadotcom の文を書く役です。出すのは開発者で、X のアプリから手で出します（開発者が決定、2026-10-08）。

全部を任せたい気持ちは分かります。けれども、フォロワー0の新しいアカウントで、最初の数本が売り込みに見えれば、「興味なし」とミュートで大きく減点されます（X の重み）。健康の効果を書かない、パチンコの語を書かない、という決まり事も、一度破れば取り消せません。AI に任せる範囲は、出した投稿の数字を見ながら広げます。

  1. 1　書く

    投稿の文を書き、要るなら動画を作る（reel.sh）。出す直前の点検5つに自分でかける。

  2. 2　見せる

    開発者に下書きを見せ、OK をもらう。直しを頼まれたら書き直す。

  3. 3　出す

    開発者が X のアプリに文を貼り、動画を付けて出す（動画は AirDrop で iPhone へ）。出した投稿の URL を Claude に伝え、記録に残す。同じ文を二度出さないため。

  4. 4　答える

    開発者が、届いた返信や質問をこの会話に貼る。AI が返事の下書きを作り、開発者が自分の言葉に直して手で出す。1つの問いに返事は1回。

03 / how

どこで動かし、誰が出すか

サーバーに AI を置き、毎日決まった時刻に動かす。最初はそう考えました。ところが、開発者が見てから出すなら、毎日の起点は開発者になります。それなら、いま使っている Claude Code のセッションで「今日の投稿を作って」と頼めば足ります。

次に考えたのは、OK のあとに API で出すことでした。ただ、X の API には下書きを置く口がなく、下書きはどのみち会話の中にあります。そして事例では、API で1件ずつ承認して出していたアカウントでも凍結されていました。1日1本なら、開発者がアプリに貼って出しても約2分です。それなら、人が画面を叩いて出すのがいちばん安全です。

決定　手で出す

開発者が Claude Code で頼む → AI が会話の中に下書き → 開発者が直して OK → 開発者が X のアプリから手で出す（開発者が決定、2026-10-08）。X の API も、自動化のラベルも要らない。費用もかからない。

あとで考える　API で出す

投稿が続き、1本2分の手間を省く価値が出てきたら。そのときは自動化のラベルを付け、1日の上限と止める仕組みを入れる。返事は API では出さない（AI の返信は X の事前の承認が要る）。

04 / implementation

作ったもの

アプリのデータにも、保存している記録にも触れません。X の API を使わないので、鍵も費用もありません。

  1. 1. スキル .claude/skills/x-post/
    「今日の投稿を作って」で動く。種類を決める → ネタを選ぶ → 書く → 画像 → 宣伝なら目標 → 自分で点検 → 見せる → 出したら記録、の手順。決まり事は docs を毎回読ませ、スキルには写さない。二重に持つと、片方だけ直して食い違う。投稿はしない。
  2. 2. 投稿の記録 marketing/x/posts.json
    出した日時、種類、型、文、画像、使ったストック、URL、返事、宣伝の目標と結果。割合を数える、同じ文を出さない、効いた型を見返す、ためのもの。
  3. 3. 紹介のストック marketing/x/sources.json
    読んだ論文と紹介したいポスト。確かめた中身を残し、下書きのたびに数字を取り違えないようにする（開発者の注文、2026-10-08）。要旨を確かめた2本を入れてある。
  4. 4. 画像のカード marketing/x/card.py
    見出し、本文、対象と出典、スクワットマンの隊列を 1200 × 675 に描く（開発者の注文、2026-10-08）。AI の画像生成は使わない。人形は動画と同じ reel_squad.swift で描く。
  5. 5. 小ネタの絵 marketing/x/gemini_image.py
    Nano Banana 2.1 に、場面の説明と、reel_squad.swift で描いたスクワットマンの見本を渡す。1枚約7円と数え、月900円で止まる（開発者の注文、2026-10-08）。

05 / cases

事例を見て、直したところ

出す前に人が見れば、凍結は避けられる。この設計の柱はそこでした。ところが、1件ずつ人が承認し、AI だと名乗っていたアカウントでも凍結されていました。人の承認が守るのは文の中身で、X が見ているのはアカウントの振る舞いです。

もう1つ、返信には別の決まりがありました。AI が書いた返信は、X の事前の承認が要る。人が見た下書きが、これに当たるかは書かれていません。

  • 決定　投稿も返事も、AI は下書きまで。開発者が直して X のアプリから手で出す（開発者が決定、2026-10-08）。
  • 提案　毎日同じ時刻に出さない。手で出すなら、自然にそうなる。
  • 提案　開発者も @yattattadotcom で手を動かす。ときどき、いいねや、手で書いた投稿を混ぜる。投稿のほかに何もしないアカウントは、凍結の理由に挙がっていた。
  • 提案　URL だけの投稿をしない。本文と動画で何のアプリか分かる投稿にする（X の縦型動画の型のとおり）。
  • 提案　良し悪しはフォロワーではなく DL で見る。App Store Connect の DL の数と、出した投稿の日時を記録に並べる。AI に30日任せた例は、65本出して売上$0だった。

06 / persona

スクワットマンとして、名乗って書く

開発者の注文は4つでした（2026-10-08）。AI の投稿には、それと分かる印を付ける。AI はスクワットマンとして話す。雑談8割、宣伝2割で出す。宣伝には、下書きの段階で24時間の目標を置き、出したあとで評価する。

声を一から作るより、アプリで起きていることを性格にしました。指が触れたらしゃがみ、2回ごとに仲間が増え、叩き切ったら床で寝る。雑談の種がアプリの中にあれば、雑談がそのままアプリの紹介にもなります。

  • 決定　AI が書いた投稿の頭に「🤖」（AI ラベル）。AI はスクワットマンとして話す。雑談8割、宣伝投稿2割。宣伝には24時間の目標（表示、いいね、リポスト）を置く（開発者の注文、2026-10-08）。
  • 提案　一人称は「ぼく」、常体の短い文、少しとぼけた声。開発者が「面白くなさすぎる」と判断し、作り直した。
  • 提案　直近10本で宣伝が2本未満、かつ前の宣伝から雑談が3本以上なら、宣伝を書いてよい。
  • 提案　最初の3本の目標は仮に、表示1,000、いいね10、リポスト2。4本目からは、これまでの中央値の1.2倍。24時間後に開発者が数を貼り、AI が達成か未達かと、次に変えることを記録する。
  • 提案　自己紹介に「🤖 の付いた投稿は、AI のスクワットマンが書いています。」を足す。
  • 決定　雑談の見本を見た開発者が「面白くなさすぎる」と判断した。雑談の大半を、スクワットの新しい研究や話題のポストの紹介にする。割合は紹介6、小ネタ2、宣伝2（開発者が決定、2026-10-08）。
  • 決定　SNS で研究を紹介してよいことにした。「こういう研究がある」で止め、対象と出典を付け、同じ投稿でアプリを勧めない。AI は要旨を読んでから書き、開発者が出典を確かめてから出す（開発者が決定、2026-10-08）。「SNS では研究の1文も書かない」という前の決まりを改めた。決まりの元は健康効果の書き方。
  • 決定　審査待ちの間から、雑談を出し始める（開発者が決定、2026-10-08）。
  • 決定　開発者が新しい口調と型を「良い感じ」と判断した。投稿に画像を付けてよい。引用した論文とポストは紹介のストックにためる（開発者の注文、2026-10-08）。画像は AI で生成せず、スクワットマンの絵と文字だけのカードにする。
  • 決定　小ネタの画像にかぎり、Gemini（Nano Banana 2.1）で描いてよい。文字を描かせない、アプリと同じ棒人間を見本に渡す、X の「AIで生成」ラベルを付ける、目で見てから使う（開発者が決定、2026-10-08）。鍵の月の上限は1,000円で、スクリプトは900円で止まる。前の「AI の画像生成は使わない」を、小ネタについて改めた。
  • 決定　宣伝のほかにも目標を置く。研究の紹介はブックマークと共有、小ネタは返信、プロフィールへのアクセス、フォローを見る。宣伝のほかは1本ごとでなく、週の振り返りでまとめて中央値を見る。最初の1週間も、根拠のない仮の目標を置く（開発者が決定、2026-10-08）。
  • 口調と文体は、X で人気のある面白いアカウントを調べてから決め直す（開発者の注文、2026-10-08）。
  • 提案　面白さは声より仕掛けから来ていた（面白いアカウントの口調）。一人称が仲間の人数で変わる（ぼく → ぼくら → 我々）、ト書き（しゃがむ）（仲間+1）、棒人間の自虐を型にする。研究の紹介は3つの型（数字と仲間の換算、〇〇派と〇〇派、いい話とただし書き）、小ネタは4つの型。見本は広報担当AI の決まり事。
