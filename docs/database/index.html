database

データベース

保存するデータの全体図。記録は Firestore に、利用者のアカウントごとに置く。表は SquatRecord の1つだけ。端末の設定は、いまどおり端末の UserDefaults に置く。

2026-10-07 の設計で、記録の置き場所を端末の SwiftData から Firestore へ移すと決めた。サーバーもアカウントも持たない、というこれまでの前提は改めた（記録を Firestore に移す）。

なぜ1つで足りるのか

画面に出る数は5つある。DT、DPW、連続記録、休み券、最長記録。どれも記録を足すか、日付順にたどれば出る。休み券の配り方と使い方には人の判断が入らないので、たどるたびに同じ答えになる。

計算で出る数を別に保存すると、記録と食い違う日が来る。たとえば将来記録の取り消しを作れば、消した1件に合わせて休み券の枚数も直さなければならない。保存するのを記録だけにしておけば、直す場所も記録だけで済む。

feature / account

アカウントと記録のつながり

アカウントは表を持たない。Firebase Authentication が Apple のログインに割り当てる番号（uid）が、そのまま記録の棚の名前になる。同じ Apple ID なら、機種を替えても Android からでも同じ uid になり、同じ棚を読む。

読み書きできるのは自分の棚だけで、記録は足すか消すだけ。この決まりはアプリではなく Firestore のルールで守る（ルール）。アカウントを削除すると、棚の記録をすべて消してからアカウントを消す。

feature / dopa-totals, streak

ドパの合計と連続記録が読むもの

ドパの合計と連続記録と休み券は、表を持たない。SquatRecord を読んで計算するだけ。直近7日間も連続の日数も、記録に書いた day から数える。端末の時刻から計算し直さないので、時差で数が動かない。

連続記録だけは、UserDefaults にも小さな値を1つ書く。途切れたことと休み券を使ったことを、どの日まで見せたか。カードと帯を1度だけ出すためで、消えても1度余計に出るだけで済む。

2026-10-06 に、フィーバータイムで取ったドパを残す列 bonusDopa を SquatRecord に足した。既定値 0 の列を足すだけなので、それより前の記録は壊れず、そのまま 0 として読める。

feature / today-reminder

今日まだ通知が読むもの

今日まだ通知は、今日の記録があるかだけを SquatRecord から読む。予約した通知そのものは iOS が持つので、アプリ側には保存しない。
