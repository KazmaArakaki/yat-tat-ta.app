SquatRecord

完了連打1回分の記録。このアプリが保存する、ただ1つの表。消えると取り戻せない唯一のデータでもある。

置き場所は Firestore の users/{uid}/records/{id}。利用者のアカウントごとの棚に置く。2026-10-07 に SwiftData から移した（記録を Firestore に移す）。

ほかの表とのつながりはない。上の users/{uid} は表ではなく、アカウントごとの棚の名前。右側も表ではなく、この表から計算する数。

columns

各カラム

カラム型中身と理由
id文書 ID（UUID）記録を見分けるための値。端末で作るときに UUID を振り、そのまま Firestore の文書の ID にする。電波がなくても、その場で決まる。今日の記録で消す1件を指すときに使う。将来の書き出しでも要る。
startedAttimestamp叩き始めた日時。最初の1打の時刻。閉じた時刻ではないのは、60秒待って閉じた記録の時刻が、叩いた時刻から1分ずれるのを避けるため。計算には使わない。今日の記録のシートに時刻（時と分）として出し、どの1件かを見分ける手がかりにする。
dayint記録日。yyyymmdd の8桁（例：20261006）。午前4時より前は前の日。最初の1打の瞬間に、端末の時刻とタイムゾーンで決めて書く。あとで startedAt から計算し直さないのは、海外へ行くと過去の記録の日が動くから。連続記録も DPW の直近7日間も、この列から数える。
repsintドパに変えたスクワットの回数。1以上。叩き切れば目標回数と同じ数、途中で閉じれば叩いたところまで。目標回数をあとで変えても、過去の記録の DT が変わらないように、その場の回数を写しておく。
bonusDopaint（既定 0）フィーバータイムで取ったドパ。フィーバーの1打はスクワットではないので、reps に混ぜず別に持つ。混ぜると、あとから何回しゃがんだかが分からなくなる。DT と DPW には reps と足して入れる。連続記録は reps のある記録で決まり、この列は見ない。2026-10-06 に足した列で、既定値 0 を持つので、それより前の記録はそのまま読める（壊さない変更）。
createdAttimestampサーバーが記録を受け取った日時。端末では書かず、Firestore の serverTimestamp で入れる。画面にも計算にも使わない。あとで「前回から増えた分だけ読む」ときの目印にするため、Firestore へ移すときに足す（課題 firestore-read-cost）。
  • 書くとき：記録を閉じたときに1件足す。閉じる条件は、残りが0、60秒叩かない、アプリを離れる、の3つ（完了連打）。叩いている間は書かない。
  • 削除：今日の記録のシートで、開発者が「消す」を押した1件だけ。消せるのは今日（記録日）の記録に限る。消したら全件を読み直して計算し直す（2026-10-06 開発者が合意）。アカウントの削除では全件を消す。更新：しない。Firestore のルールでも書き換えを断る（ルール）。
  • 件数：毎食後に3回叩いても、1年で1,000件ほど。起動時に全件を読んで計算する。Firestore では読んだ件数で費用がかかる（課題 firestore-read-cost）。
