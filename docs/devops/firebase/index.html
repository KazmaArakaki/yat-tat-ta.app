Firebase の準備と運用

2026-10-07 設計。Firebase の設定を触るとき、記録の列を変えるとき、ルールを変えるときに開く。

決まり事

  • Firebase で使うのは、Authentication（Apple のログイン）、Firestore、Hosting（公開ページ）の3つだけ。
  • GoogleService-Info.plist は Git に入れない。
  • テストと計測モードは Firestore に触れない。メモリ版の RecordStore を使う。
  • 記録の列を足したり変えたりしたら、同じコミットでルールも直し、開発用と本番用の両方に反映する。
  • firebase deploy には毎回 -P dev か -P prod を付ける。既定のプロジェクトは置かない。

setup

最初の準備（約35分）

開発者のアカウントでしかできない作業です。実装を始める前に1回だけ。

  1. 1
    Firebase のプロジェクトを作る（約10分）
    Firebase コンソールでプロジェクトを作る。Google アナリティクスは入れない（集める理由がなく、プライバシーの表示が増える）。iOS アプリを足し、バンドル ID に com.yat-tat-ta を入れる。
  2. 2
    設定ファイルを置く（約2分）
    ダウンロードした GoogleService-Info.plist を ios/YatTatTa/ に置く。.gitignore に入れてあるので、Git には入らない。ないままビルドすると、起動した瞬間に落ちる。
  3. 3
    Firestore を作る（約5分）
    Firestore Database を作る。場所は東京（asia-northeast1）。あとから変えられない。始めは本番モード（全部断る）で作り、すぐ下のルールを反映する。
  4. 4
    Apple のログインを有効にする（約15分）
    Authentication の Sign-in method で Apple を有効にし、「OAuth コードフローの構成」も埋める。iPhone だけならログイン自体には要らないが、アカウントを削除するときに Apple との連携を切る処理（トークンの取り消し）が、この構成を使う。いずれ Android からログインするときにも要る。
    埋める値は4つ。① サービス ID：Apple Developer の Identifiers で Services ID を作る（例 com.yat-tat-ta.signin）。Sign in with Apple を有効にし、Domains に {プロジェクト ID}.firebaseapp.com、Return URL に Firebase の画面に出る https://{プロジェクト ID}.firebaseapp.com/__/auth/handler を入れる。② Team ID：K334V22YZ3。③ 鍵の ID と ④ 秘密鍵：Apple Developer の Keys で Sign in with Apple の鍵を作り、ダウンロードした .p8 の中身を貼る。.p8 は1回しかダウンロードできず、Git にも入れない。
  5. 5
    ルールを反映する（約3分）
    リポジトリの firebase/ で、npx firebase-tools login（初回だけ）のあと npx firebase-tools deploy --only firestore:rules -P dev と -P prod を実行する。反映するまでは本番モードのまま全部断るので、アプリから記録を書けない。ルールを変えたら、そのたびに反映する。

environments

開発用と本番用（約30分）

開発用と本番用でプロジェクトを分けています。Debug（Xcode の Run）は開発用の yat-tat-ta-dev、Release（TestFlight と App Store）は本番用の yat-tat-ta に書きます。設定ファイルは、ビルドの途中でスクリプトがアプリへ写します。

App Check で、Firestore は本物のアプリからの問い合わせだけを受け付けます。Release は App Attest、Debug はデバッグ用のトークンです。開発用のプロジェクトを作るときの手順は次のとおり。

  1. 1
    開発用のプロジェクトを作る（約10分）
    Firebase コンソールで yat-tat-ta-dev を作る（ID が取れなければ、Firebase が付ける末尾ごと使い、firebase/.firebaserc の dev を直す）。Google アナリティクスは入れない。iOS アプリを足し、バンドル ID は本番と同じ com.yat-tat-ta。
  2. 2
    Firestore を作る（約5分）
    場所は東京（asia-northeast1）、本番モード。ルールを反映するより先に作る。Firestore がないまま firebase deploy すると、firebase-tools が置き場所を聞かずに米国（nam5）に作ってしまい、あとから変えられない（2026-10-07、開発用で一度起きた。消して作り直した）。
  3. 3
    Apple のログインを有効にする（約5分）
    Authentication で Apple を有効にし、OAuth コードフローの構成に本番と同じ値（Services ID com.yat-tat-ta.signin、Team ID、鍵の ID、秘密鍵）を入れる。Apple Developer の Services ID の設定で、Domains に yat-tat-ta-dev.firebaseapp.com、Return URLs に https://yat-tat-ta-dev.firebaseapp.com/__/auth/handler を足す。
  4. 4
    設定ファイルを置く（約3分）
    開発用の GoogleService-Info.plist を ios/Firebase/Dev/ に、本番用（いまの ios/YatTatTa/ にあるもの）を ios/Firebase/Prod/ に置く。どちらも Git には入らない。
  5. 5
    App Check を登録する（約5分）
    Apple Developer の Identifiers で com.yat-tat-ta に App Attest を足す。両方のプロジェクトの App Check で、iOS アプリに App Attest を登録する。App Attest の Team ID は K334V22YZ3。アプリはバンドル ID が com.yat-tat-ta のものを選ぶ（Services ID の com.yat-tat-ta.signin と取り違えやすい）。Debug で初めて起動すると、Xcode のコンソールに「App Check debug token」が出るので、開発用のプロジェクトの App Check の「アプリ」タブで、アプリの「⋮」→「デバッグトークンを管理」に登録する。端末ごとに違い、シミュレーターは入れ直すたびに変わる。トークンは Git に入れない。
  6. 6
    ルールを両方に反映し、App Check で断り始める（約3分）
    firebase/ で npx firebase-tools deploy --only firestore:rules -P dev。本番は反映済み。両方のプロジェクトの App Check で、Cloud Firestore の「適用」を押す。

security rules

ルール

アプリに埋め込む鍵は、誰でも取り出せます。他人の記録を読ませない、壊れた記録を書かせないのは、このルールです。置き場所は firebase/firestore.rules。

createdAt はサーバーの時刻（serverTimestamp）でしか書けません。電波のないところで叩いた記録も、送られた時点でサーバーが時刻を入れるので、ルールを通ります。

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function isValidRecord(d) {
      return d.keys().hasOnly(['startedAt', 'day', 'reps', 'bonusDopa', 'createdAt'])
        && d.keys().hasAll(['startedAt', 'day', 'reps', 'bonusDopa', 'createdAt'])
        && d.startedAt is timestamp
        && d.day is int && d.day >= 20260101 && d.day <= 99991231
        && d.reps is int && d.reps >= 1 && d.reps <= 1000
        && d.bonusDopa is int && d.bonusDopa >= 0
        && d.createdAt == request.time;
    }

    // 自分の棚だけ。記録は足すか消すだけで、書き換えない
    match /users/{uid}/records/{recordId} {
      allow read, delete: if request.auth != null && request.auth.uid == uid;
      allow create: if request.auth != null && request.auth.uid == uid
        && isValidRecord(request.resource.data);
      allow update: if false;
    }
  }
}

hosting

公開ページ

プライバシーポリシーとサポートのページを、Firebase Hosting で https://yat-tat-ta.web.app/ に出しています。元のファイルは firebase/public/ です。

  • 出す前の確認：開発用のコンテナの reverse-proxy が、firebase/public/ を http://site.yat-tat-ta.localhost/ で返す（.devcontainer/reverse-proxy）。ファイルを直せば、再読み込みで反映される。
  • 出し方：firebase/ で npx firebase-tools deploy --only hosting -P prod。ルールとは別に出せる。開発用には出さない。
  • 日本語と英語は同時に直す：/privacy/ と /privacy/en/、/ と /en/。片方だけ直すと、言語で書いてあることが食い違う。
  • ポリシーを変えたら改定日を書く：制定日の下に「改定日：」を足す。集める情報を増やすときは、出す前にポリシーを直す。
  • 外のフォントやスクリプトを読み込まない：開いた人の情報を、ほかのサービスへ送らないため。
  • URL を変えない：アプリと App Store Connect が同じ URL を開く。変えるとアプリを出し直すことになる。
