devops / 発信 提案：開発者のレビュー待ち

SNS で発信するときの決まり事

投稿や動画を出す前に開く。決まりは7つと、出す直前の点検が5つ。どれもSNS で売る事例の調査から引いた。

why

ストアより、投稿のほうが慎重に

App Store の説明文には、健康の効果も、パチンコの語も、慎重に外しました。説明文は審査の人が読み、年齢制限の答えと照らされるからです。

SNS の投稿は、誰にも審査されません。だから緩めていい、と考えたくなる。けれども、投稿のほうが条件は悪いのです。説明文には研究の1文の前後に注意書きを置けましたが、15秒の動画のキャプションにはその余地がない。掲載情報でキーワードに健康の語を入れなかったのと、同じ理由です。

しかも、ステマ規制で処分されるのは、投稿を頼んだ側です。インフルエンサーではなく、アプリを作った人が問われます。

rules

決まり

表1　SNS で発信するときの決まり（2026-10-07 に読んだ規約と法令による）
#決まり理由
1アプリと体の効果を結ばない。研究は「こういう研究がある」で止め、対象と出典を付けた紹介の投稿でだけ書く。紹介の投稿でアプリを勧めない。痩せる、治る、病気の名前、「〇%下がる」の言い切りは書かない投稿は前後の文脈を持ちにくい。研究の紹介の決まりは健康効果の書き方の SNS の節。2026-10-08 に「SNS では研究の1文も書かない」から改めた（開発者が決定）
2パチンコ、スロット、ギャンブル、くじ、当たりの語を書かない。演出の言葉（激熱、FEVER）は、画面にあるとおり見せてよいストアの掲載情報の決まり4と揃える。ストアで避けた語を SNS で使えば、ストアで避けた意味が薄れる。ドパ〇〇の他のアプリがパチンコ風を名乗っていても、真似しない
3人に頼んだ投稿、物や値引きやお金を渡した投稿には、冒頭に分かりやすく「PR」か「広告」を出させる。TikTok はブランドコンテンツの設定、X は Paid Partnership のラベルを使う。自分のアカウントは、プロフィールに作った本人だと書くステマ規制（2023/10/1 施行）。処分されるのは頼んだ側。ハッシュタグの山に #PR を紛れ込ませるのも、分かりにくい表示とされうる。表示のない投稿は TikTok のおすすめに載らないことがある
4★やレビューと引き換えに、何も渡さない。アプリの中で評価を頼むなら、Apple の仕組み（SKStoreReviewController）だけを使うApp Store 審査ガイドライン 5.6.1 と 3.2.2。お金や見返りでレビューを集めると、Developer Program から除かれることもある。高評価と引き換えの割引は、日本でステマ規制の措置命令になった（2024/6、2025/3）
5動画に映すのは、ストアに出ている版の本物の画面。まだない機能や、作り物の映像を映さない審査ガイドライン 2.3.1（誤解を招く宣伝）。優良誤認も疑われうる。Pushscroll は作る前に「動くアプリ」風の動画で需要を試したが、この手は使わない
6Reddit などのコミュニティでは、場の決まりを先に読む。アプリに触れる投稿は全体の1〜2割まで。アカウントを1つにし、仲間に投票を頼まない複数のアカウントや身内の投票は見抜かれ、永久 BAN になった例がある（F5）
7動画の主役はスクワットマン。AI で作った人を映さない。もし使うことになったら、TikTok と YouTube の AI 生成の表示を付け、実在の利用者の感想のように見せない開発者が決定（2026-10-07）。スクワットマンはアプリの本物の素材で、明らかにアニメなので AI の表示も要らない。本物に見える AI の人は、TikTok と YouTube で表示が要り、架空の利用者に感想を言わせれば誤解を招く宣伝になる

check

出す直前の点検（約1分）

  1. 1　アプリを使うと体がこうなる、と読めないか。研究の紹介なら、対象と出典があり、アプリを勧めていないか
  2. 2　パチンコ、ギャンブルの語はないか（キャプション、ハッシュタグ、動画の文字）
  3. 3　映っている画面は、ストアに出ている版のものか
  4. 4　人に頼んだ投稿なら、冒頭に PR の表示があるか
  5. 5　「★5を付けて」「レビューで〇〇」と書いていないか

account

X のアカウント

投稿は、アプリ専用の新しいアカウントから出す（開発者が決定、2026-10-07）。フォロワー0から始まるので、最初の投稿はアプリの公開日まで取っておく。リンクを貼れない投稿は、見た人が DL まで進めない。

自己紹介に「作った本人が運用している」と書く。決まり事の3のとおり、誰が言っているかを見て分かるようにするため。

make

動画の作り方（約3分）

cd ios && Design/reel.sh を実行すると、ios/Design/Reels/reel-ja.mp4 ができる。iPhone 18 Pro のシミュレーターで、演出の見本 -demo reel を見本の記録で流して録り、アプリが書いた音、上の帯の文字、終わりのアイコンとアプリ名を重ねる。

引数で言語と種類を選べる：Design/reel.sh [ja|en] [sns|lp]（既定は ja と sns、2026-10-09）。sns は SNS の縦動画で、叩き切ったところまで（約24秒、reel-{ja,en}.mp4）。lp はLPの動画で、叩き切ったあとの共有の誘いを4.5秒見せてから終わる（約29秒、lp-{ja,en}.mp4。アプリに -reelShare を渡す）。英語はアプリの画面も英語で録る。英語の帯の文字は1行に収まるよう短く言い直し、文字も小さくしてある（CAPTION_SIZE）。

X に出す動画と本文の型はX の縦型動画のグッドとバッドに従う。上の帯に出す文字は ios/Design/compose_reel.py の CAPTIONS（言語ごと。最後の行は lp のときだけ出す）、終わりの画面の文字は CARD_TITLE と CARD_LINE で変える。表1の1と2に従う。叩く間隔やフィーバーを当てる打数は、アプリの AppModel.Reel にある。作り方を決めたセッションはSNS で売る事例の調査。

sources

出典と、確かめていないこと

  • 消費者庁「ステルスマーケティングに関する景品表示法の規制」 caa.go.jp
  • App Store Review Guidelines（2.3.1、3.2.2、5.6.1） developer.apple.com と、評価とレビューの頼み方 developer.apple.com
  • TikTok のブランドコンテンツ tiktok.com
  • YouTube の AI で作った・加工した内容の開示 blog.youtube。TikTok の AI 生成の表示は業者の解説（storrito.com）で読んだだけで、公式の文面は未確認
  • X の Paid Partnerships ポリシー（2026年3月にラベルを導入） help.x.com

景品表示法は、専門家に確かめていません。人にお金を払って投稿を頼むときは、その前に消費者庁の Q&A を読み直します。X のプラットフォームの操作についての規約は、取りにいくと読めませんでした。
