処理落ちの確かめ方

2026-10-06 決定。演出を足したとき、重くしたとき、ストアに出す前に開く。

決まり事

演出を足したり重くしたりしたら、実機の計測モードで100打を叩き、指と基準値で確かめる。
結果は、その演出を作ったセッションのページに書く。

起動引数
-perf
Debug ビルドだけ。記録はメモリの中だけで、アプリを終えれば消える。
端末
iPhone 15 Pro（120Hz）
低電力モードは切る。入っていると 60Hz に絞られる。

steps

手順（10分）

  1. 1
    Xcode の Scheme の Arguments に -perf を足して、実機に入れる
  2. 2
    100打を全力で叩き切る。最後の1打でフィーバーが当たるので、10秒間画面全体を叩き続ける。フィナーレは最後まで見る（飛ばすと、そこでまとめの札になる）
  3. 3
    まとめの札をスクリーンショットする。「もう1回」で、あと2回繰り返す
  4. 4
    途中で手が止まったら、札の右の ↺ でやり直す。終わったら Arguments の -perf を外す。付けたままだと、ふだんの記録が残らない

scene

計測モードで起きること

  • 目標回数100。60打目でスクワット隊が上限の30人そろう
  • 最後の1打でフィーバータイムが必ず当たる
  • 同じ1打で DT 1,000（金のドパ突破）と DPW ベスト更新をまたぐ。フィーバーが終わると記録が閉じ、連続記録30日を足した札3枚のフィナーレが出る

いちばん重い場面が変わったら（隊の上限を上げた、新しい全画面の演出を足した、など）、仮の記録とこの一覧を直す。

criteria

合格の線と基準値

最後に決めるのは開発者の指です。指で遅れも抜けも感じず、声を1回も切っていなければ合格。札の数字は、演出を足す前より悪くなっていないかを見るために使います。比べる相手は、2026-10-06 の実機3回目の数字（基準値）です。

札の色もこの線で塗る。赤は基準値から1割以上悪い（描画の最低 70 未満、詰まり 3 回以上、発火の最大 80ms 超）。黄は基準値の範囲だが、最初に決めた線（描画 100、発火 40ms）の外。1回の数字はぶれるので、赤が出たら3回叩いて、続けて出るかを見る。

線を2段にした経緯はセッションのページ。

blind spot

札に出ない詰まり

札の描画の数字は、アプリの側の詰まりだけを数えます。画面を合成する側（render server）で飛んだコマは見えません。札がすべて緑なのに指が重いと感じたら、Mac につないで Instruments の Animation Hitches を選び、同じ100打を録ります。
